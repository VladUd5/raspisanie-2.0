# Расписание 2.0

Лабораторный стенд, который показывает сквозной цикл обработки данных
**сбор → очистка → анализ** на расписании занятий Вавиловского университета.

- **Сбор** — парсер [`mbfuss/smart_schedule_parser`](https://github.com/mbfuss/smart_schedule_parser)
  обходит сайт вуза, скачивает PDF-расписания и отдаёт их содержимое в JSON.
- **Очистка** — стенд разбирает текст каждой ячейки PDF на тип занятия,
  дисциплину, преподавателей и аудитории, склеивает опечатки и разные
  написания, отбрасывает служебные строки и помечает сомнительные случаи.
- **Анализ** — веб-интерфейс на Streamlit: загруженность преподавателей,
  аудиторий, дисциплин и групп таблицами и графиками, сквозные фильтры,
  выгрузка в CSV и Excel.

## Быстрый старт (Docker)

Нужны Docker и Docker Compose v2.

```bash
git clone --recurse-submodules <адрес этого репозитория>
cd "Расписание 2.0"
docker compose up --build
```

Откройте <http://localhost:8501>. В репозитории уже лежит демо-снапшот
(`data/snapshots/`), поэтому стенд сразу показывает данные — даже без
интернета.

Чтобы собрать свежие данные с сайта, на странице **«Обзор и пайплайн»**
нажмите **«Собрать данные с сайта»**. Парсер обойдёт сайт и скачает все PDF —
это занимает несколько минут. Новый снапшот появится в списке в боковой
панели; старые остаются доступны для сравнения.

Если репозиторий склонирован без `--recurse-submodules`:

```bash
git submodule update --init
```

## Запуск без Docker

Нужен Python 3.10+. Работает на демо-снапшоте; кнопка сбора сообщит, что
парсер недоступен (если не запустить его отдельно).

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r stand/requirements.txt
streamlit run stand/app.py
```

Чтобы кнопка сбора работала локально, запустите только парсер с пробросом
порта на `localhost:8080` и укажите стенду его адрес:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d parser
PARSER_URL=http://localhost:8080 streamlit run stand/app.py
```

## Что есть в стенде

Фильтры в боковой панели действуют на всех страницах, кроме «Словаря написаний»: снапшот, корпус,
институт, форма обучения, группа, день недели, неделя (числитель/знаменатель),
тип занятия и переключатель «считать числитель/знаменатель полной парой».

| Страница | Что показывает |
|---|---|
| Обзор и пайплайн | кнопка сбора, три этапа цикла со счётчиками, занятия по институтам, история снапшотов |
| Преподаватели | недельная нагрузка каждого преподавателя по всем институтам и формам; топ по часам; теплокарта «день × время» и разбивка по типам занятий для выбранного; его занятия на неделю |
| Аудитории | загруженность кабинетов; матрица «кабинет × дисциплина»; теплокарта недели выбранной аудитории; основные корпуса / прилегающие здания |
| Дисциплины | часы, преподаватели и группы по дисциплинам; часы по типам занятий |
| Группы | расписание группы сеткой «день × время» после очистки; нагрузка по дням |
| Качество данных | доля распознанных полей, занятия с флагами проверки и исходным текстом ячейки, отброшенные служебные строки |
| Словарь написаний | каждое слово (дисциплина, преподаватель, аудитория, группа, тип занятия) со всеми его написаниями, которые посчитаны вместе: разница подсвечена, у каждого — вид ошибки (опечатка, сокращение, лишний пробел, регистр…); сколько можно доверять автоправилам |
| Данные и экспорт | все занятия выборки одной таблицей; выгрузка CSV и Excel (4 листа) |

## Как считается нагрузка

- По умолчанию в фильтрах выбрана **очная** форма обучения: у заочной и
  очно-заочной расписание сессионное, их «неделя» с неделей очников
  несопоставима. Фильтр можно снять.
- Длительность занятия — по времени из расписания (пара — 1.5 часа).
- Занятие только по числителю или только по знаменателю идёт раз в две
  недели и считается как **0.5** пары (переключатель в боковой панели
  считает его полной парой).
- **Поточная лекция** для нескольких групп в PDF записана в ячейке каждой
  группы. Преподавателю и аудитории она засчитывается **один раз**: события
  с одинаковыми днём, временем, неделей, типом занятия и дисциплиной
  считаются одним.
- Если в одной ячейке PDF оказалось несколько занятий (так бывает, когда
  конвертер склеивает объединённые ячейки), каждое получает `1/n` нагрузки
  этого слота: по PDF нельзя понять, на какой неделе идёт каждое.
- Занятие с несколькими преподавателями засчитывается каждому из них
  полностью.
- Один слот «день × время» занимает у преподавателя или аудитории **не
  больше одной пары в неделю**. Если в расписании в один слот стоят разные
  занятия (ошибка в PDF), они делят эту пару; такие наложения перечислены на
  странице «Качество данных».
- Аудитория определяется парой (корпус, номер): 202 в УК1 и 202 в УК2 — разные
  кабинеты. Если корпус в тексте не указан, берётся корпус института.

## Как устроена очистка

Парсер отдаёт текст ячейки PDF целиком, например:

```
лек. ИСТОРИЯ МИРОВОЙ КУЛЬТУРЫ ст.пр. Аленичева Н.В. 314
пр. Управление сбытом в агробизнесе Воронова, Ларюков 316
лаб.з. Химия 328, 334 Логачева Е.А. , Цыгулева Э.И.
```

Модуль `stand/etl/clean.py` разбирает его по шагам:

1. схлопывает разрядку (`С К О Т О В О Д С Т В О` → `СКОТОВОДСТВО`);
2. отбрасывает служебное (`переход на УК 2`, `Кураторский час`, `* * *`);
3. вырезает часы (`4 лек. + 5 пр.`, `(28)`), время (`с 13.40`) и звания;
4. находит места, записанные словами, по справочнику `stand/etl/locations.py`
   (физ. зал, СОК, Кванториум, кафедры, именованные лаборатории);
5. режет ячейку на занятия по маркерам типа (`лек.`, `пр.з.`, `лаб.з.`,
   `ЗАЧЕТ`…);
6. в каждом занятии находит подгруппу, корпус, аудитории, преподавателей
   (с инициалами и без) и дисциплину.

Затем разные написания одного и того же сводятся к канону
(`Иностанный язык` → `Иностранный язык`, `ЦИФР. ТЕХНОЛ. В ЗАЩИТЕ РАСТЕНИЙ` →
`Цифровые технологии в защите растений`, `Потоцкая` → `Потоцкая Л.Н.`):

1. сначала по **проверенному вручную словарю** `stand/etl/dictionary/*.csv` —
   для снапшота 2026-10-07 в нём все написания дисциплин, преподавателей,
   групп и маркеров типа;
2. написания, которых в словаре нет (новый сбор), — по автоправилам
   `stand/etl/normalize.py`; такие занятия помечаются флагом «написание не
   проверено»;
3. иначе написание остаётся как есть.

Что с чем объединено — на странице «Словарь написаний». Там же сверка
автоправил со словарём: на снапшоте 2026-10-07 правила верно склеивают 95%
пар написаний дисциплин и находят 74% нужных склеек (преподаватели — 98% и
82%), поэтому словарь, а не правила — основной источник канона. Как дополнять
словарь — в `stand/etl/dictionary/README.md`.

На реальных данных (4005 уникальных строк, октябрь 2026) распознаётся:
тип занятия — 97%, дисциплина — 99%, преподаватель — 98%, аудитория — 97%.

### Как пополнить справочник мест

Если на странице «Качество данных» видны занятия, где место записано
словами и не распознано, добавьте строку в `LOCATIONS` в
`stand/etl/locations.py`:

```python
_loc(r"(?<![А-ЯЁа-яё])теплица(?![А-ЯЁа-яё])", "Теплица", ADJACENT, re.I),
```

Третий аргумент — корпус: `ADJACENT` («Прилегающие здания») или `None`
(аудитория корпуса института). После правки удалите `data/schedule.db` и
перезапустите стенд — снапшоты загрузятся заново.

## Структура

```
docker-compose.yml          parser + stand
vendor/smart_schedule_parser   парсер (git submodule, не модифицируется)
stand/
  app.py                    точка входа Streamlit, навигация, фильтры
  views/                    8 страниц
  ui/                       кэш чтения БД, фильтры, тема
  charts/common.py          графики Plotly
  analytics/queries.py      агрегаты для отчётов
  etl/                      collect → flatten → clean → canon (словарь, normalize) → load
  etl/dictionary/           проверенный словарь написаний (CSV) и как его дополнять
  labels.py                 русские названия институтов, форм, колонок
data/
  snapshots/*.json          снапшоты (ответ парсера с датой сбора)
  schedule.db               SQLite, создаётся автоматически
tests/                      pytest
docs/                       дизайн и план
```

Схема БД описана в `stand/etl/load.py` (`SCHEMA`).

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Ключевые наборы:

- `tests/test_clean.py` — 113 реальных строк из PDF с ручной разметкой;
- `tests/test_clean_corpus.py` — все 4005 строк корпуса: разбор не падает,
  доля распознанных полей не ниже порогов;
- `tests/test_analytics.py` — правила счёта нагрузки на маленьком снапшоте;
- `tests/test_dictionary.py`, `tests/test_canon.py`, `tests/test_variants.py` — словарь
  написаний, порядок «словарь → правила → как есть», вид ошибки;
- `tests/test_smoke.py` — каждая страница стенда открывается без ошибок;
- `tests/test_demo_snapshot.py` — настоящий снапшот из `data/snapshots`
  грузится и открывается на всех страницах, все его написания проверены словарём.

## Если что-то не работает

- **Сбор пишет `lookup www.vavilovsar.ru … server misbehaving`.** Внутри
  Docker не сработал DNS — обычно это разовый сбой, нажмите «Собрать» ещё
  раз. Если повторяется, проверьте, открывается ли сайт вуза с этого
  компьютера.
- **Сбор пишет «Сбор уже идёт».** Кто-то запустил сбор в другой вкладке;
  дождитесь его окончания (до 15 минут). Если стенд перезапускали во время
  сбора, блокировка снимется сама через 15 минут.
- **`docker compose up` падает на `pip install … Read timed out`.** Медленный
  доступ к PyPI — запустите команду ещё раз.
- **В боковой панели нет снапшотов.** Положите JSON-снапшот в
  `data/snapshots/` или нажмите «Собрать данные с сайта».
- **Поменяли код очистки, а данные старые.** Удалите `data/schedule.db` и
  перезапустите стенд — снапшоты загрузятся заново. После правки словаря
  написаний и после обновления стенда с новой схемой БД это происходит
  автоматически (в Docker — после `docker compose up --build -d stand`).
- **Локальный запуск после Docker пишет `attempt to write a readonly database`.**
  Файлы в `data/` контейнер создаёт от root. Удалите `data/schedule.db`
  (папка ваша, sudo не нужен) — стенд создаст базу заново.

## Ограничения

Это ограничения исходных данных и парсера; стенд их не прячет, а подсвечивает
на странице «Качество данных».

1. Парсер называет дни недели по порядку их появления в PDF. Если день
   пропущен, метки сдвигаются; группы с занятиями «в воскресенье»
   показываются как подозрительные.
2. Если имена групп в PDF записаны в одной ячейке через пробел, парсер режет
   их по пробелу (`1 бэ` → `1` и `бэ`). Такие группы помечаются
   подозрительными.
3. Каждый запрос к парсеру — полный обход сайта и скачивание всех PDF
   (несколько минут).
4. Конвертер PDF склеивает объединённые ячейки: в одной ячейке оказываются
   несколько занятий, а название лекции повторяется по числу групп. Стенд
   режет такие ячейки; неделю каждого куска восстановить нельзя.
5. Часть ячеек приходит с оборванным началом или без дисциплины.
6. На сайте бывают битые ссылки на PDF — парсер их пропускает.
7. Расписание заочников устроено сессиями, а не неделями; оно загружается
   как есть, и «недельная» нагрузка для него условна.
