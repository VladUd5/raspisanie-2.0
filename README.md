# Расписание 2.0

Расписание занятий Вавиловского университета в двух версиях:

- **для студентов и преподавателей** (`/`) — найти свою группу, преподавателя или аудиторию с
  телефона, увидеть изменения, подписаться на расписание в календаре, сообщить об ошибке;
- **для руководства** (`/rukovodstvo`) — нагрузка преподавателей, загрузка аудиторий, дисциплины,
  группы, изменения в расписании, сообщения пользователей, выгрузка в Excel.

Данные собираются автоматически: парсер
[`VladUd5/smart_schedule_parser`](https://github.com/VladUd5/smart_schedule_parser) (форк
[`mbfuss/smart_schedule_parser`](https://github.com/mbfuss/smart_schedule_parser), ветка
`geometriya`) дважды в день обходит сайт вуза и раскладывает PDF-расписания по видимой сетке, а
стенд разбирает текст ячеек на тип занятия, дисциплину, преподавателей и аудитории и склеивает
разные написания одного и того же.

## Запуск (Docker)

Нужны Docker и Docker Compose v2.24+.

```bash
git clone --recurse-submodules <адрес этого репозитория>
cd "Расписание 2.0"
cp .env.example .env        # поправьте порт, адрес сайта, даты весеннего семестра
docker compose up -d --build
```

Откройте `http://<сервер>/` — сайт для студентов, `http://<сервер>/rukovodstvo/` — версия для
руководства. В репозитории лежит снапшот расписания (`data/snapshots/`), поэтому сайт сразу
показывает данные; свежие данные collector соберёт в ближайшее время из `COLLECT_TIMES`.

Контейнеры:

| Контейнер | Что делает |
|---|---|
| `parser` | обходит сайт вуза, скачивает PDF, отдаёт JSON |
| `collector` | сбор по расписанию (`COLLECT_TIMES`, по умолчанию 03:00 и 13:00 по Саратову) и по кнопке «Проверить сайт сейчас»; загрузка в базу, публикация, изменения. Единственный, кто пишет в `schedule.db` |
| `public` | сайт для студентов и преподавателей (FastAPI, порт 8000) |
| `staff` | версия для руководства (Streamlit, порт 8501, путь `/rukovodstvo`) |
| `proxy` | nginx: `/` → public, `/rukovodstvo` → staff; наружу один порт `HTTP_PORT` |

Если у вуза свой nginx, контейнер `proxy` можно не поднимать: образец настройки — `deploy/nginx.conf`
(для `/rukovodstvo` обязательно проксирование WebSocket).

Собрать данные вручную, не дожидаясь расписания: `docker compose exec collector python collector.py once`.

### Какой нужен сервер

Замеры: данные одной версии расписания (6,5 тыс. занятий) занимают в памяти около 11 МБ и читаются
за 0,07 с; актуальное расписание собирается за 0,2 с; страница группы отдаётся за 20–60 мс и весит
около 4 КБ в сжатом виде; образ стенда — около 650 МБ, парсера — 200 МБ.

- **Рекомендуется:** 2 vCPU, 4 ГБ RAM, 20 ГБ диска. Минимум: 1 vCPU, 2 ГБ RAM.
- Трафик при ~20 посетителях в час — порядка десятков мегабайт в час; пик (выкладка расписания,
  начало семестра, 100–200 человек одновременно) студенческий сайт выдерживает без заметной нагрузки.
  Версия для руководства (Streamlit) держит соединение на каждого открытого пользователя — она
  рассчитана на единицы-десятки одновременных пользователей.
- Хранятся только версии, которые чем-то отличаются: около 50 в год, ~65 МБ JSON и ~200 МБ в базе.
- Для подписки на календарь сайт должен быть доступен из интернета по HTTPS (`PUBLIC_URL`).

### Настройки (`.env`)

Все параметры и значения по умолчанию — в `.env.example`. Главное:

- **Даты семестров.** Семестр всегда начинается с верхней недели, дальше верхняя и нижняя
  чередуются. Осень по умолчанию 1 сентября – 31 декабря, **весну нужно задать** перед её началом
  (`SPRING_START=2027-02-09`). Пока сегодняшняя дата не попадает в семестр, студенты видят обе
  недели с пометками, а календарь очников пуст; версия руководства об этом предупреждает.
- `PUBLIC_URL` — публичный адрес сайта (ссылки в календаре).
- Пороги публикации и изменений: `PUBLISH_MIN_RATIO`, `MAJOR_CHANGE_RATIO`, `CHANGE_BADGE_DAYS`.

Версия для руководства открыта по адресу, без логинов. Поэтому на сайте нет ничего, что нельзя
показывать посторонним: сообщения анонимные (контакт не собирается), а даты семестров меняются
только в `.env` на сервере.

## Как обновляются данные

1. **Сбор.** collector запрашивает парсер. Если ответ совпадает с последним сохранённым снапшотом,
   он не сохраняется — в `data/status.json` пишется только время проверки.
2. **Публикация.** Снапшот, в котором занятий меньше `PUBLISH_MIN_RATIO` (70%) от прошлого, не
   публикуется: сайт вуза мог отдать не всё. Студенты продолжают видеть прошлую версию,
   руководство — предупреждение на «Сводке».
3. **Актуальное расписание.** Очники и очно-заочники — из последней опубликованной версии.
   Заочники — **архив недель**: каждая неделя сессии хранится, даже когда её сняли с сайта вуза;
   для каждой даты берётся версия, актуальная на день занятия (поздние правки прошедших дат историю
   не переписывают, переделки недели не суммируются).
4. **Изменения.** Каждая опубликованная версия сравнивается с предыдущей после очистки и склейки
   написаний: добавлено, отменено, изменено (было → стало), перенесено. Новая неделя сессии
   заочников — одна строка «новая неделя»; будущая неделя, снятая с сайта, — «неделя снята»; если в
   форме обучения изменилось больше `MAJOR_CHANGE_RATIO` (30%) занятий — одна строка «новое
   расписание» (так выглядит начало семестра). Прошедшие даты не сравниваются.

Совет к первому запуску: снапшот `2026-10-07_*.json` собран старой версией парсера (верхняя и
нижняя неделя в одной ячейке), поэтому изменения между ним и `2026-10-09_*.json` — в основном
разница парсеров, а не расписания. Если это мешает, удалите старый файл из `data/snapshots/` до
запуска.

## Сайт для студентов и преподавателей

| Адрес | Что там |
|---|---|
| `/` | поиск с подсказками (группа, преподаватель, аудитория; регистр, дефисы и опечатки не важны), закреплённые и недавно открытые страницы, последние изменения |
| `/g/<группа>` | вкладки «Расписание» и «Аналитика». Расписание: на компьютере — сетка недели «пары × дни», на телефоне — полоса дней и карточки выбранного дня; сверху карточка «Сейчас / Следующая» (аудитория, сколько осталось); цвет карточки — тип занятия (лекция, практика, лабораторная, зачёт/экзамен), в карточке отдельными строками аудитория и преподаватель; пометки «изменено / замена / отменено / перенесено», подробности и «Сообщить об ошибке» — по щелчку на занятие; у очников — только занятия текущей верхней или нижней недели, у заочников — неделя сессии, стрелки листают архив; `?sub=1` — только общие занятия и 1-я подгруппа |
| `/t/<преподаватель>`, `/r/<корпус>/<аудитория>` | то же для преподавателя (поток — одно занятие со списком групп) и аудитории; занятия всех форм обучения, у заочных и очно-заочных — пометка «заочн.» / «оч.-заочн.»; переключатель «Все формы / Очная / …» (`?form=och`, `ochzaoch`, `zaoch`), если форм несколько |
| `/d/<дисциплина>` | то же для дисциплины: все её занятия по группам |
| `?view=stats` | вкладка «Аналитика» у группы, преподавателя, аудитории и дисциплины: часы за неделю, месяц и семестр (прошло / осталось), по месяцам, дням, типам и формам, занятость аудитории по парам, таблица дисциплин или групп; `&format=xlsx` — та же таблица в Excel |
| `/changes` | изменения за период с поиском |
| `/g/<группа>.ics`, `/t/<преподаватель>.ics` | подписка на календарь; `?sub=1` — общие занятия и 1-я подгруппа; у преподавателя `?form=och` / `ochzaoch` / `zaoch` — только одна форма обучения |
| `POST /report` | «Сообщить об ошибке» в подробностях занятия: анонимно, не больше `REPORTS_PER_HOUR` сообщений в час с адреса |

Страницы работают без JavaScript (он нужен для подсказок в поиске, переключения дней без перезагрузки
и закрепления страниц), светлая и тёмная тема — по настройке телефона. Шрифт Golos Text (OFL)
лежит рядом с сайтом, внешних запросов страница не делает.

**Кафедры и контакты.** Раз в сутки collector собирает справочник с официального сайта вуза
(`data/directory.json`): кафедры из «Сведений об образовательной организации» (`/sveden/struct`) —
заведующий, телефон, почта, страница; должности и степени — из списка ППС
(`/sveden/employees/pps`); состав, преподавательская и опубликованная рабочая почта — со страниц
кафедр. На странице преподавателя — «Контакты», в подробностях занятия — кафедра. Показывается
только то, что вуз публикует сам. Обновить вручную: `docker compose exec collector python collector.py directory`.

**Сессии.** Календарные учебные графики лежат на сайте вуза сканами PDF (`/sveden/education/eduop`).
collector раз в сутки находит новые графики, распознаёт отметки «Э» (сессия) по курсам и кладёт
черновики в `data/feedback.db`; учебный отдел проверяет их на странице «Сессии» версии для руководства
(скан рядом, даты можно поправить) и подтверждает. Студенты видят только подтверждённые даты: на
вкладке «Аналитика» группы и плашкой на расписании за месяц до сессии, вместе с ближайшими зачётами
и экзаменами из расписания. Группа сопоставляется с графиком по коду в названии файла («Б-ЛА») и
курсу — первой цифре номера («Б-ЛА-301» → 3 курс). Графики без кода группы (колледж) пропускаются,
код можно вписать вручную. Разобрать заново все файлы: `docker compose exec collector python collector.py kug --all`.

Первый сбор после смены парсера: если в старом снапшоте пара «каждую неделю» склеивала несколько
вариантов, а новый разбор разделил их на верхнюю и нижнюю неделю, это не считается изменением.

## Версия для руководства

Оформление — в стиле сайта для студентов: тема, цвета и шрифт задаются в `stand/.streamlit/config.toml`
(светлая и тёмная), логотип и шрифт — в `stand/static/`.

Фильтры в боковой панели действуют на всех страницах: институт, форма обучения, корпус, группа,
неделя сессии (у заочников); в «Дополнительно» — день, верхняя/нижняя неделя, тип занятия,
«считать полной парой», академические или астрономические часы.

| Страница | Что показывает |
|---|---|
| Сводка | когда проверяли сайт вуза, предупреждения (сбор не удался или неполный, неделя снята, нет дат семестра), изменения за неделю, новые сообщения, ключевые цифры |
| Преподаватели | недельная нагрузка каждого преподавателя; топ по часам; теплокарта «день × время» и разбивка по типам для выбранного; его занятия |
| Аудитории | загруженность кабинетов; матрица «кабинет × дисциплина»; теплокарта недели аудитории |
| Дисциплины | часы, преподаватели и группы по дисциплинам |
| Группы | пары в неделю у групп; сетка группы «день × время»; нагрузка по дням |
| Инфографика | распределения нагрузки, пиковые часы, загрузка аудиторного фонда, свободные аудитории по слотам |
| Изменения | все изменения за период с фильтрами, выгрузка в Excel |
| Сообщения | сообщения пользователей: статус «новое → в работе → исправлено / отклонено», заметка, журнал действий |
| Сессии | черновики дат сессий из графиков учебного процесса: скан графика, правка, подтверждение, кнопка «Проверить графики» |
| Выгрузка | все занятия по фильтрам, CSV и Excel (4 листа) |
| *Служебное:* История сборов | статус сбора, кнопка «Проверить сайт сейчас» (не чаще раза в 10 минут), даты семестров, версии и их публикация |
| *Служебное:* Качество данных, Словарь написаний | для сопровождающего: доля распознанных полей, флаги проверки, как склеены написания |

**Верхняя и нижняя неделя.** Пара в PDF делится пополам: занятие в верхней половине ячейки идёт по
верхней неделе, в нижней — по нижней (в JSON парсера — `numerator`/`denominator`).

**Неделя сессии.** Заочное расписание выкладывается по неделям, у каждого занятия есть дата. По
умолчанию выбрана последняя неделя сессии; в режиме «все недели вместе» нагрузка заочников — сумма
за все недели архива (каждое занятие — по версии на его дату), а пиковые часы и загрузка аудиторного
фонда — в среднем за неделю.

## Запуск без Docker (разработка)

Нужен Python 3.10+.

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
(cd stand && python collector.py load)          # база из data/snapshots
(cd stand && uvicorn public.app:app --reload)   # сайт для студентов: http://localhost:8000
streamlit run stand/app.py                      # версия для руководства: http://localhost:8501
```

Чтобы собрать свежие данные, поднимите только парсер с пробросом порта и запустите сбор:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d parser
(cd stand && PARSER_URL=http://localhost:8080 python collector.py once)
```

## Как считается нагрузка

- По умолчанию в фильтрах выбрана **очная** форма обучения: у заочной и
  очно-заочной расписание сессионное, их «неделя» с неделей очников
  несопоставима. Фильтр можно снять.
- Длительность занятия — по времени из расписания. По умолчанию часы
  **академические** (45 минут, пара — 2 ак. часа): в них считают учебную
  нагрузку. Переключатель «Часы» в боковой панели показывает астрономические
  (пара — 1.5 часа); число пар от единицы не зависит.
- Занятие только по верхней или только по нижней неделе идёт раз в две
  недели и считается как **0.5** пары (переключатель в боковой панели
  считает его полной парой).
- **Поточная лекция** для нескольких групп в PDF записана в ячейке каждой
  группы. Преподавателю и аудитории она засчитывается **один раз**: события
  с одинаковыми днём, временем, неделей, типом занятия и дисциплиной
  считаются одним.
- Если в одной ячейке PDF записано несколько занятий (подгруппы в одной
  ячейке), каждое получает `1/n` нагрузки этого слота.
- Занятие с несколькими преподавателями засчитывается каждому из них
  полностью.
- Один слот «день × время» занимает у преподавателя или аудитории **не
  больше одной пары в неделю**. Если в расписании в один слот стоят разные
  занятия (ошибка в PDF), они делят эту пару; такие наложения перечислены на
  странице «Качество данных».
- Аудитория определяется парой (корпус, номер): 202 в УК1 и 202 в УК2 — разные
  кабинеты. Если корпус в тексте не указан, берётся корпус института.

## Как устроена очистка

Парсер отдаёт текст ячейки PDF целиком, например:

```
лек. ИСТОРИЯ МИРОВОЙ КУЛЬТУРЫ ст.пр. Аленичева Н.В. 314
пр. Управление сбытом в агробизнесе Воронова, Ларюков 316
лаб.з. Химия 328, 334 Логачева Е.А. , Цыгулева Э.И.
```

Модуль `stand/etl/clean.py` разбирает его по шагам:

1. схлопывает разрядку (`С К О Т О В О Д С Т В О` → `СКОТОВОДСТВО`);
2. отбрасывает служебное (`переход на УК 2`, `Кураторский час`, `* * *`);
3. вырезает часы (`4 лек. + 5 пр.`, `(28)`), время (`с 13.40`) и звания;
4. находит места, записанные словами, по справочнику `stand/etl/locations.py`
   (физ. зал, СОК, Кванториум, кафедры, именованные лаборатории);
5. режет ячейку на занятия по маркерам типа (`лек.`, `пр.з.`, `лаб.з.`,
   `ЗАЧЕТ`…);
6. в каждом занятии находит подгруппу, корпус, аудитории, преподавателей
   (с инициалами и без) и дисциплину.

Затем разные написания одного и того же сводятся к канону
(`Иностанный язык` → `Иностранный язык`, `ЦИФР. ТЕХНОЛ. В ЗАЩИТЕ РАСТЕНИЙ` →
`Цифровые технологии в защите растений`, `Потоцкая` → `Потоцкая Л.Н.`):

1. сначала по **проверенному вручную словарю** `stand/etl/dictionary/*.csv` —
   для снапшота 2026-10-07 в нём все написания дисциплин, преподавателей,
   групп и маркеров типа;
2. написания, которых в словаре нет (новый сбор), — по автоправилам
   `stand/etl/normalize.py`; такие занятия помечаются флагом «написание не
   проверено»;
3. иначе написание остаётся как есть.

Что с чем объединено — на странице «Словарь написаний». Там же сверка
автоправил со словарём: на снапшоте 2026-10-07 правила верно склеивают 95%
пар написаний дисциплин и находят 74% нужных склеек (преподаватели — 98% и
82%), поэтому словарь, а не правила — основной источник канона. Как дополнять
словарь — в `stand/etl/dictionary/README.md`.

На реальных данных (4005 уникальных строк, октябрь 2026) распознаётся:
тип занятия — 97%, дисциплина — 99%, преподаватель — 98%, аудитория — 97%.

### Как пополнить справочник мест

Если на странице «Качество данных» видны занятия, где место записано
словами и не распознано, добавьте строку в `LOCATIONS` в
`stand/etl/locations.py`:

```python
_loc(r"(?<![А-ЯЁа-яё])теплица(?![А-ЯЁа-яё])", "Теплица", ADJACENT, re.I),
```

Третий аргумент — корпус: `ADJACENT` («Прилегающие здания») или `None`
(аудитория корпуса института). После правки удалите `data/schedule.db` и
перезапустите стенд — снапшоты загрузятся заново.

## Если что-то не работает

- **На «Сводке»: «Сбор не удался: lookup www.vavilovsar.ru … server misbehaving».** Внутри Docker не
  сработал DNS — обычно разовый сбой, следующий сбор пройдёт. Если повторяется, проверьте, открывается
  ли сайт вуза с сервера. Студенты всё это время видят прошлую версию.
- **«Сбор выглядит неполным».** Сайт вуза отдал заметно меньше занятий, чем в прошлый раз; версия не
  опубликована. Если расписание действительно сократилось, удалите прошлые снапшоты или поменяйте
  `PUBLISH_MIN_RATIO`.
- **`docker compose up` падает на `pip install … Read timed out`.** Медленный доступ к PyPI —
  запустите команду ещё раз.
- **Студенты видят обе недели вместо верхней/нижней.** Сегодня вне семестра: задайте даты в `.env`
  и перезапустите (`docker compose up -d`).
- **Поменяли код очистки, а данные старые.** Удалите `data/schedule.db` и перезапустите — снапшоты
  загрузятся заново, изменения пересчитаются. `data/feedback.db` не удаляйте: там сообщения
  пользователей.
- **Локальный запуск после Docker пишет `attempt to write a readonly database`.** Файлы в `data/`
  контейнер создаёт от root. Удалите `data/schedule.db*` — база создастся заново.

## Ограничения

Это ограничения исходных данных и парсера; стенд их не прячет, а подсвечивает
на странице «Качество данных».

1. Каждый запрос к парсеру — полный обход сайта и скачивание всех PDF
   (несколько минут).
2. На сайте бывают битые ссылки на PDF — парсер их пропускает.
3. Парсер строит таблицу по видимым линиям листа. То, чего на листе нет
   (преподаватель, аудитория, дата в таблице заочного файла «от 14.09»), он
   не додумывает. Где подпись времени забыта, время берётся по стандартной
   сетке пар; где дата в ячейке дня не читается, она берётся по неделе — с
   предупреждением в логе парсера.
4. Расписание заочников устроено сессиями, а не неделями: нагрузка считается
   внутри выбранной недели сессии.
