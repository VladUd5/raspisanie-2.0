# Расписание 2.0

Расписание занятий Вавиловского университета:

- **`/`** — сайт для студентов и преподавателей: расписание группы, преподавателя, аудитории,
  изменения, подписка на календарь, сообщения об ошибках;
- **`/rukovodstvo`** — версия для руководства: нагрузка, аудиторный фонд, изменения, сообщения
  пользователей, графики учебного процесса, выгрузка в Excel.

Источник данных — PDF-расписания на сайте вуза. Их обходит парсер
[`VladUd5/smart_schedule_parser`](https://github.com/VladUd5/smart_schedule_parser) (git submodule,
ветка `geometriya`), стенд разбирает ячейки на занятия и сводит разные написания к одному.

Памятка для отдела ИТ — [`docs/pamyatka-it.md`](docs/pamyatka-it.md).

## Состав

| Контейнер | Назначение |
|---|---|
| `parser` | обход сайта вуза, разбор PDF, ответ в JSON |
| `collector` | фоновые задачи (см. «Расписание задач»); единственный, кто пишет в `schedule.db` |
| `public` | сайт для студентов (FastAPI, порт 8000) |
| `staff` | версия для руководства (Streamlit, порт 8501) |
| `proxy` | nginx: `/` → `public`, `/rukovodstvo` → `staff`; наружу один порт `HTTP_PORT` |

Если у вуза свой nginx, `proxy` можно не поднимать; образец настройки — `deploy/nginx.conf`
(для `/rukovodstvo` нужен WebSocket).

## Требования

- Linux x86-64, Docker Engine и Docker Compose v2.24+, git.
- Рекомендуется 2 vCPU, 4 ГБ RAM, 20 ГБ диска; минимум 2 vCPU, 2 ГБ RAM, 10 ГБ.
- Для подписки на календарь сайт должен быть доступен из интернета по HTTPS (`PUBLIC_URL`).

Ориентиры: одна версия расписания (6,5 тыс. занятий) — около 11 МБ в памяти; страница группы
формируется за 20–60 мс и весит около 4 КБ в сжатом виде; архив версий растёт примерно на 65 МБ
JSON в год. Версия для руководства держит соединение на каждого пользователя и рассчитана на
десятки одновременных пользователей.

## Установка

```bash
sudo systemctl enable --now docker
git clone --recurse-submodules https://github.com/VladUd5/raspisanie-2.0.git "Расписание 2.0"
cd "Расписание 2.0"
cp .env.example .env              # PUBLIC_URL, при необходимости HTTP_PORT
docker compose up -d --build      # первая сборка — около 12 минут
docker compose ps                 # public, staff, collector, proxy — (healthy)
```

В репозитории есть снапшот расписания (`data/snapshots/`), поэтому сайт показывает данные сразу.

## Настройки

Все параметры с описанием — в `.env.example`; ни один не обязателен.

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `PUBLIC_URL` | — | внешний адрес сайта (ссылки на календарь) |
| `HTTP_PORT` | `80` | внешний порт |
| `COLLECT_DAYS`, `COLLECT_TIMES` | `пн,чт`, `03:00` | дни и время сбора расписания |
| `AUTUMN_START` … `SPRING_END` | из графиков | даты семестров, если нужно задать вручную |
| `HOLIDAYS_EXTRA`, `WORKDAYS_EXTRA` | — | ручная правка праздников |
| `PUBLISH_MIN_RATIO` | `0.7` | порог полноты сбора для публикации |
| `MAJOR_CHANGE_RATIO` | `0.3` | порог «новое расписание» в ленте изменений |
| `BACKUP_KEEP_DAYS` | `14` | сколько резервных копий хранить |

Версия для руководства открыта без авторизации; на ней нет персональных данных — сообщения
анонимные, настройки меняются только в `.env` на сервере.

## Эксплуатация

### Расписание задач

| Задача | Когда | Вручную |
|---|---|---|
| Сбор расписания | `COLLECT_DAYS` в `COLLECT_TIMES`; кнопка «Проверить сайт сейчас» на «Сводке» | `docker compose exec collector python collector.py once` |
| Графики учебного процесса | ежедневно после 04:00; кнопка на странице «Сессии» | `… collector.py kug` (`--all` — разобрать все заново) |
| Резервная копия | ежедневно после 04:00 и при старте | `… collector.py backup` |
| Справочник кафедр | раз в 30 дней | `… collector.py directory` |

Время — по часовому поясу `TZ_NAME` (Europe/Saratov).

### Обновление

```bash
git pull --recurse-submodules
docker compose up -d --build
```

Во время сборки работает прежняя версия; при пересоздании контейнеров сайт недоступен несколько
секунд. Данные (`data/`) и настройки (`.env`) не затрагиваются. Откат:
`git checkout <коммит> && git submodule update && docker compose up -d --build`.

### Резервные копии

`data/backups/ГГГГ-ММ-ДД.tar.gz` содержит то, что нельзя получить с сайта вуза заново:
`feedback.db` (сообщения, подтверждённые графики) и снапшоты (архив недель заочников). Копии лежат
на том же диске — их нужно забирать на другой сервер, например `rsync` по cron.

Восстановление:

```bash
docker compose down
sudo tar -xzf data/backups/2026-10-14.tar.gz -C data/
sudo rm -f data/schedule.db*          # пересоберётся из снапшотов
docker compose up -d
```

### Отказоустойчивость

| Сбой | Реакция |
|---|---|
| Процесс упал | Docker перезапускает контейнер (`restart: unless-stopped`) |
| `public` или `staff` не отвечает | `stand/healthcheck.py` после 3 неудачных проверок перезапускает контейнер (~1,5 мин) |
| `collector` завис | нет пульса 40 минут — перезапуск |
| Перезагрузка сервера | контейнеры стартуют вместе со службой Docker |
| Наплыв запросов | nginx: 20 запросов/с (запас 100) и 60 соединений на адрес, сверх — 429; `public` — не больше 64 одновременных запросов на процесс, сверх — 503 |
| Утечка памяти | у каждого контейнера свой `mem_limit` |
| Рост логов | не больше 3 файлов по 10 МБ на контейнер |

Если перед сайтом стоит прокси вуза, в `deploy/nginx.conf` нужно указать `set_real_ip_from <адрес
прокси>` и `real_ip_header X-Forwarded-For`, иначе ограничения на адрес станут общими для всех.

Журналы: `docker compose logs --since 1h <контейнер>`; перезапуски: `docker compose ps -a`.

## Данные

### Сбор и публикация

1. **Сбор.** Ответ парсера, совпадающий с последним снапшотом, не сохраняется — в
   `data/status.json` записывается только время проверки.
2. **Публикация.** Снапшот, в котором занятий меньше `PUBLISH_MIN_RATIO` от прошлого, не
   публикуется: студенты видят прошлую версию, на «Сводке» — предупреждение.
3. **Актуальное расписание.** Очная и очно-заочная формы — последняя опубликованная версия.
   Заочная — архив недель: каждая неделя сессии хранится и после снятия с сайта, для каждой даты
   берётся версия, актуальная на день занятия.
4. **Изменения.** Каждая версия сравнивается с предыдущей: добавлено, отменено, изменено,
   перенесено; новая или снятая неделя заочников и массовое обновление формы обучения
   (больше `MAJOR_CHANGE_RATIO`) — одной строкой. Прошедшие даты не сравниваются.

### Учебный календарь

- **Семестры** — по графикам учебного процесса очной и очно-заочной форм, если не заданы в `.env`.
  Верхняя и нижняя недели чередуются от недели 1 сентября. Источник дат — в «Истории сборов».
- **Праздники** — производственный календарь РФ, переносы по графикам вуза, `HOLIDAYS_EXTRA` и
  `WORKDAYS_EXTRA`.
- **Графики учебного процесса** (`/sveden/education/eduop`, сканы PDF) распознаются ежедневно: новые
  и заменённые на сайте (по ETag и Last-Modified). Периоды курсов — теория, сессия, каникулы,
  практика — попадают в черновики; учебный отдел проверяет и подтверждает их на странице «Сессии».
  Графики без признаков ошибки распознавания подтверждаются одной кнопкой.
- Студенты видят только подтверждённые периоды. В сессию, каникулы, практику и праздники
  еженедельные пары не показываются и не учитываются в часах и календаре; зачёты, экзамены и
  консультации показываются всегда. Группа сопоставляется с графиком по коду («Б-ЛА») и курсу
  (первая цифра номера группы).

### Справочник кафедр

`data/directory.json` — кафедры, заведующие и контакты (`/sveden/struct`), должности и степени
(`/sveden/employees/pps`), состав кафедр и рабочая почта (страницы кафедр). Используется в
карточке преподавателя и в подробностях занятия. Обновляется раз в 30 дней; при недоступности
сайта остаётся прежний файл.

### Очистка

`stand/etl/clean.py` разбирает текст ячейки на тип занятия, дисциплину, преподавателей, подгруппу,
корпус и аудитории; места, записанные словами, — по `stand/etl/locations.py`. Написания сводятся к
канону по проверенному словарю `stand/etl/dictionary/*.csv`, затем по автоправилам
`stand/etl/normalize.py` (такие занятия помечаются «написание не проверено»). Порядок пополнения
словаря — [`stand/etl/dictionary/README.md`](stand/etl/dictionary/README.md).

Доля распознанных полей на реальных данных: тип занятия — 97%, дисциплина — 99%, преподаватель —
98%, аудитория — 97%.

### Расчёт нагрузки

- По умолчанию — очная форма и академические часы (пара — 2 ак. часа); переключатели в боковой панели.
- Занятие по верхней или нижней неделе — 0,5 пары в неделю.
- Поточная лекция засчитывается преподавателю и аудитории один раз.
- Несколько занятий в одной ячейке делят слот поровну; занятие с несколькими преподавателями
  засчитывается каждому полностью.
- Слот «день × время» даёт преподавателю или аудитории не больше одной пары в неделю; наложения —
  на странице «Качество данных».
- Аудитория определяется парой «корпус, номер».

## Сайт для студентов

| Адрес | Содержание |
|---|---|
| `/` | поиск по группам, преподавателям и аудиториям; закреплённые страницы; последние изменения |
| `/g/<группа>` | расписание недели, карточка «Сейчас / Следующая», пометки изменений; `?sub=1` — 1-я подгруппа |
| `/t/<преподаватель>`, `/r/<корпус>/<аудитория>`, `/d/<дисциплина>` | то же для преподавателя, аудитории, дисциплины; `?form=och\|ochzaoch\|zaoch` |
| `?view=stats` | аналитика: часы за неделю, месяц, семестр; `&format=xlsx` — Excel |
| `/changes` | изменения за период |
| `/g/<группа>.ics`, `/t/<преподаватель>.ics` | подписка на календарь |
| `POST /report` | сообщение об ошибке (анонимно, не больше `REPORTS_PER_HOUR` в час с адреса) |
| `/healthz` | проверка работоспособности |

Страницы работают без JavaScript, поддерживают светлую и тёмную тему и не обращаются к внешним
ресурсам.

## Версия для руководства

Фильтры боковой панели (институт, форма обучения, корпус, группа, неделя сессии и др.) действуют на
всех страницах.

| Страница | Содержание |
|---|---|
| Сводка | состояние сбора, «Проверить сайт сейчас», предупреждения, изменения за неделю, ключевые показатели |
| Преподаватели, Аудитории, Дисциплины, Группы | нагрузка, загрузка, теплокарты |
| Инфографика | распределение нагрузки, пиковые часы, свободные аудитории |
| Изменения | изменения за период, выгрузка в Excel |
| Сообщения | сообщения пользователей и их статусы |
| Сессии | проверка и подтверждение графиков учебного процесса |
| Выгрузка | занятия по фильтрам, CSV и Excel |
| История сборов, Качество данных, Словарь написаний | служебные страницы |

## Разработка

Python 3.10+:

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
(cd stand && python collector.py load)          # база из data/snapshots
(cd stand && uvicorn public.app:app --reload)   # http://localhost:8000
streamlit run stand/app.py                      # http://localhost:8501
pytest
```

Свежие данные без Docker-стека:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d parser
(cd stand && PARSER_URL=http://localhost:8080 python collector.py once)
```

## Неполадки

| Симптом | Причина и действие |
|---|---|
| «Сбор не удался: lookup www.vavilovsar.ru …» | сбой DNS в Docker, обычно разовый; при повторе проверить доступ к сайту вуза с сервера |
| «Сбор выглядит неполным» | сайт вуза отдал заметно меньше занятий; если сокращение настоящее — снизить `PUBLISH_MIN_RATIO` |
| Сборка падает на `pip install … Read timed out` | медленный доступ к PyPI — повторить |
| У очников обе недели вместо верхней или нижней | дата вне семестра или графики нового года ещё не разобраны; проверить «Историю сборов», при необходимости задать даты в `.env` |
| Изменён код очистки, данные старые | удалить `data/schedule.db*` и перезапустить (`feedback.db` не удалять) |
| Локально `attempt to write a readonly database` | файлы `data/` созданы контейнером от root — удалить `data/schedule.db*` |

## Ограничения

- Каждый сбор — полный обход сайта и всех PDF (несколько минут); битые ссылки пропускаются.
- Парсер не восстанавливает то, чего нет на листе (преподаватель, аудитория, дата). Пропущенное
  время берётся из стандартной сетки пар.
- Нагрузка заочников считается внутри недели сессии.
