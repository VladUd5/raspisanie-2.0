# Расписание 2.0 — дизайн лабораторного стенда

Дата: 2026-10-07
Статус: согласован с заказчиком, ожидает вычитки спеки

## Цель

Лабораторный стенд, который показывает сквозной цикл обработки данных
**сбор → очистка → анализ** на примере расписания Вавиловского университета.
Студенты работают со стендом интерактивно: переключают страницы, ставят
фильтры, смотрят таблицы и графики, выгружают результаты.

Источник требований — файл `ТЗ` в корне репозитория.

## Принятые решения

| вопрос | решение |
|---|---|
| платформа стенда | Python + Streamlit, хранилище SQLite, графики Plotly |
| источник данных | кнопка «Собрать данные» (живой парсинг) + демо-снапшот в репозитории |
| парсер | `mbfuss/smart_schedule_parser` подключён git submodule и **не модифицируется**; вся очистка — в нашем ETL |
| запуск | `docker compose up`, стенд на `http://localhost:8501` |
| документация | собственный `README.md` на русском |

## Исходные данные: что реально отдаёт парсер

`GET /getschedule?urlSchedule=www.vavilovsar.ru/ucheba/raspisanie-zanyatii`
возвращает массив корпусов:

```
Building{name, institutes[]}
  Institute{name, forms[]}
    StudyForm{name, groups[]}
      Group{name, schedule{days[]}}
        Day{name, lessons[]}
          Lesson{time_from, time_to, subject, week?}
```

- `name` корпуса/института/формы — slug из URL (`uk1`, `institut-agrobiznesa`,
  `ochnaya-forma-obucheniya`).
- `week` отсутствует → занятие на обеих неделях; иначе `numerator` / `denominator`.
- Поля `Lecturer` и `Room` в апстриме закомментированы. **`subject` содержит
  весь текст ячейки PDF**: тип занятия, дисциплину, преподавателя(ей),
  аудиторию(и), а также опечатки источника. Примеры из реального PDF:

```
лек. ИСТОРИЯ МИРОВОЙ КУЛЬТУРЫ ст.пр. Аленичева Н.В. 314
пр.з. Физическая культура и сорт Кузьмин 422
пр.з .Иностанный язык Раздобарова, Бормосова 450, 528
Экономическая культура доц. Васильева Е.А. (5 лек.), Ерзова (5 пр.з.) 232
лек. ТЕОРИЯ СИСТЕМ И СИСТЕМНЫЙ АНАЛИЗ доц. Косарев А.А. 134 к
```

Следствие: отчёты по преподавателям и аудиториям из ТЗ невозможны без
стадии очистки. Это центральная часть стенда.

## Архитектура

```
[vavilovsar.ru] --PDF--> parser (Go, :8080)
                              │ JSON                       СБОР
                              ▼
                 data/snapshots/<YYYY-MM-DD_HHMMSS>.json
                              │                            ОЧИСТКА
                              ▼
          flatten → clean → normalize → load (SQLite data/schedule.db)
                              │                            АНАЛИЗ
                              ▼
                     stand (Streamlit, :8501)
```

Два сервиса в `docker-compose.yml`:

- `parser` — сборка из `vendor/smart_schedule_parser` его собственным
  `docker/Dockerfile`; при старте `HOST` в `.env` подменяется на `0.0.0.0`
  (как в апстрим-compose). Порт наружу не обязателен.
- `stand` — Python 3.10 + Streamlit. Обращается к парсеру по
  `PARSER_URL=http://parser:8080`. Том `./data` смонтирован в контейнер.

Без Docker стенд запускается локально (`streamlit run stand/app.py`) на
демо-снапшоте; кнопка сбора в этом режиме сообщает, что парсер недоступен.

### Компоненты

| модуль | ответственность | вход → выход |
|---|---|---|
| `etl/collect.py` | HTTP-запрос к парсеру, сохранение снапшота | URL → путь к `.json` |
| `etl/flatten.py` | разворот вложенного JSON в плоские строки | JSON → `list[RawLesson]` |
| `etl/clean.py` | разбор `subject`: отсев служебного, разрезание на занятия, поля | `str` → `ParsedCell` |
| `etl/locations.py` | справочник словесных аудиторий (прилегающие здания, именованные лаборатории) | — (данные: регулярка → аудитория, корпус) |
| `etl/normalize.py` | канонизация дисциплин и ФИО, fuzzy-дедуп | список имён → маппинг вариант→канон + журнал |
| `etl/load.py` | оркестрация ETL и запись в SQLite | снапшот → `snapshot_id` |
| `analytics/queries.py` | агрегаты для отчётов (чистые функции над DataFrame) | DataFrame + фильтры → DataFrame |
| `charts/*.py` | построители фигур Plotly | DataFrame → Figure |
| `app.py`, `pages/*.py` | UI: сайдбар-фильтры и страницы | — |

Модули ETL и аналитики не импортируют Streamlit — тестируются отдельно.

## Модель данных (SQLite)

```
snapshots(id PK, collected_at, source_url, file_name,
          groups_cnt, cells_cnt, lessons_cnt, service_cnt)

cells(id PK, snapshot_id FK,               -- одна ячейка PDF = одна строка subject
      building, institute, study_form, group_name,
      day, day_idx, time_from, time_to, duration_h,
      week_type,                           -- both | numerator | denominator (из парсера)
      subject_raw,
      is_service,                          -- служебная строка, занятий не порождает
      lessons_in_cell)                     -- сколько занятий получилось после разрезания

lessons(id PK, cell_id FK, snapshot_id FK,
        part_idx,                          -- номер занятия внутри ячейки
        lesson_type,   -- лекция | практика | лабораторная | семинар | консультация | зачёт | экзамен | не определён
        discipline_id FK NULL,
        subgroup NULL,                     -- 1, 2, … ; NULL = вся группа
        building,                          -- корпус из текста (УК2, ФТИК) или корпус из иерархии парсера
        week_factor)

disciplines(id PK, name)                     -- каноническое название
discipline_aliases(alias PK, discipline_id)  -- варианты написания

teachers(id PK, full_name, surname)
lesson_teachers(lesson_id FK, teacher_id FK)

rooms(id PK, building, name)                 -- аудитория уникальна в паре (корпус, номер)
lesson_rooms(lesson_id FK, room_id FK)

quality(lesson_id PK FK, has_type, has_discipline, has_teacher, has_room,
        discipline_fuzzy, teacher_surname_only, split_cell,
        suspicious_group, needs_review)

merges(snapshot_id, kind, alias, canonical, score)  -- журнал fuzzy-склеек
```

Повторный ETL того же снапшота заменяет его данные (идемпотентность).
Служебные строки сохраняются в `cells` (для страницы качества), но занятий
не порождают и в нагрузку не входят.

### Счёт нагрузки

- `duration_h = time_to − time_from` в часах (пара 1.5 ч).
- `week_factor = 0.5` для числителя/знаменателя, `1.0` для обеих недель.
- Недельная нагрузка = Σ `duration_h × week_factor`.
- Переключатель в сайдбаре «считать числитель/знаменатель полной парой»
  заменяет `week_factor` на 1.0.
- Занятие с несколькими преподавателями засчитывается каждому полностью;
  с несколькими аудиториями — каждой аудитории полностью.
- **Разрезанная ячейка.** Если из одной ячейки получилось `n > 1` занятий,
  а парсер считает её занятием на обе недели, то это, скорее всего,
  чередование (числитель/знаменатель или подгруппы склеились при конвертации
  PDF). Каждое занятие получает `week_factor = 1/n` и флаг `split_cell`.
  Если у ячейки уже есть числитель/знаменатель — `0.5/n`.
- Переключатель «считать числитель/знаменатель полной парой» ставит
  `week_factor = 1.0` всем занятиям, включая разрезанные.

## Правила очистки (`clean.py`)

Вход — одна строка `subject` (одна ячейка PDF). Выход:

```
ParsedCell(is_service: bool, lessons: list[ParsedLesson])
ParsedLesson(lesson_type, discipline | None, teachers: list[str],
             rooms: list[str], building | None, subgroup | None)
```

Конвейер (порядок важен):

1. **Предобработка.** `\n` → пробел, схлопывание пробелов, `trim`.
   Схлопывание разрядки: 3+ одиночные заглавные буквы через одиночный пробел
   склеиваются (`С К О Т О В О Д С Т В О` → `СКОТОВОДСТВО`,
   `А С У Т П` → `АСУТП`, `п е р е е з д` → `переезд`).
2. **Служебные фрагменты.** Вырезаются `переход на УК N`, `переезд( на УК N)?`,
   `Кураторский час`, `*`. Если после этого не осталось ни одной буквы —
   ячейка служебная: `is_service = true`, `lessons = []`.
3. **Аннотации часов** вырезаются до поиска типов, чтобы не создать ложное
   занятие и ложную аудиторию: `N лек. + M пр.`, `(N лек.)`, `(N пр.з.)`,
   `(N)` сразу после фамилии.
4. **Места в прилегающих зданиях** распознаются по справочнику
   `etl/locations.py` **до** разрезания и заменяются плейсхолдером. Иначе
   `лаб. Акуш.` в конце строки будет принят за маркер второго лабораторного
   занятия. Каждая запись справочника — **отдельная аудитория** со своим
   корпусом. Справочник на старте:

   | шаблон в тексте | аудитория | корпус |
   |---|---|---|
   | `физ. зал`, `физ.зал`, `(физ. зал)` | Физ. зал | Прилегающие здания |
   | `сок` (отдельным словом) | СОК | Прилегающие здания |
   | `каф.ФиС`, `каф. ФиС`, `.каф. ФиС`, `КФиС` | Кафедра ФиС | Прилегающие здания |
   | `каф. Терап.` | Кафедра терапии | Прилегающие здания |
   | `кванториум`, `Кванториум` | Кванториум | Прилегающие здания |
   | `АГРОЦЕНТР, корпус ФТИК, ауд. N.` | Агроцентр ФТИК, ауд. N | Прилегающие здания |
   | `лаб. Акуш.` | Лаб. акушерства | корпус института |
   | `лаб.Эпизоотологии`, `лаб. Эпизоот.` | Лаб. эпизоотологии | корпус института |
   | `лаб. Паразитологии` | Лаб. паразитологии | корпус института |
   | `лаб.Патанат`, `лаб.Пат.Анат.` | Лаб. патанатомии | корпус института |
   | `лаб.анатомии`, `лаб.Анатомии` | Лаб. анатомии | корпус института |

   «Прилегающие здания» — групповая метка корпуса для фильтра, а не одно
   место: Физ. зал, СОК и Кванториум остаются разными аудиториями.
   «Корпус института» — корпус из иерархии парсера; все именованные
   лаборатории встречаются только в расписаниях институтов УК3, как и
   `ауд. Большая` / `ауд. Малая`.

   Справочник — обычный Python-список «регулярка → название, корпус».
   Пополнять его можно без правки логики. Строки, где после ФИО остался
   нераспознанный хвост без цифр, попадают на страницу качества: так
   находятся новые места.
5. **Разрезание на занятия.** Маркер типа занятия (регистронезависимо, точка и
   пробел внутри опциональны):

   | маркер | тип |
   |---|---|
   | `лек` | лекция |
   | `пр.з`, `пр з`, `пр. з`, `пр.з .`, `пр.` (без «з») | практика |
   | `лаб.з`, `лаб. з`, `лаб.`, `лб.з` | лабораторная |
   | `сем` | семинар |
   | `конс` | консультация |
   | `ЗАЧЕТ`, `зачёт` | зачёт |
   | `ЭКЗАМЕН` | экзамен |

   Маркер — отдельное слово (не часть слова), не предварён цифрой или `(`.
   Строка режется перед каждым маркером, кроме первого. Текст до первого
   маркера, если он есть (`2-я подгруппа …`), присоединяется к первому
   занятию. Нет ни одного маркера — одно занятие с типом «не определён».
6. **Внутри каждого занятия:**
   1. **Подгруппа**: `Nп/г`, `N п/г`, `N-я подгруппа`, `N подгруппа` →
      `subgroup = N`, фрагмент вырезается.
   2. **Корпус**: `УК N`, `(УК N)`, `УК №N`, `УКN` → `building = "УКN"`;
      `корпус X` → `building = "X"`. Фрагмент вырезается вместе с
      предшествующими словами-локациями в капсе (`АГРОЦЕНТР,`).
   3. **Аудитории**, в любом месте строки:
      - `ауд. N`, `ауд.N`, `ауд .N` — N из 1–4 цифр с необязательной литерой;
      - `С-N` (буквенный корпус) — сохраняется как `С-N`;
      - отдельное число из 3–4 цифр с необязательной литерой (`518а`,
        `431 а` → `431а`), не входящее в ФИО и не являющееся частью времени;
      - именованные: `ауд. Большая`, `ауд. Малая` → `Большая`, `Малая`
        (аудитории основного корпуса института);
      - места из справочника (шаг 4) — с корпусом из справочника;
      - разделители между несколькими аудиториями — `,`, `/`, пробел.
      Порядок аудиторий — как в строке.
   4. **Звания** вырезаются: `доц.`, `доцент`, `проф.`, `проф`, `профессор`,
      `ст. пр.`, `ст.пр.`, `ст.преп.`, `преп.`, `асс.` — в том числе слитно
      с фамилией (`доц.Измайлова`).
   5. **Преподаватели с инициалами**: `Фамилия И.О.`, `Фамилия И. О.`,
      `Фамилия И.О` (без последней точки), `Фамилия ЕД.` (без точки между
      инициалами), `Фамилия Е.Н .` (оторвавшаяся точка), в том числе без
      пробела перед следующим ФИО (`Ю.С.Чернышев`). Канон: `Фамилия И.О.`
   6. **Преподаватели без инициалов**: слово с заглавной буквы и строчными
      далее, стоящее **после** дисциплины, — в хвостовой части строки,
      соседствующей с другими ФИО, аудиториями, запятыми или концом строки.
      Слово внутри названия дисциплины фамилией не считается.
   7. **Дисциплина** — то, что осталось между маркером типа и первым
      преподавателем или аудиторией. Повтор капсового названия схлопывается
      до одного (`ИСТОРИЯ РОССИИ ИСТОРИЯ РОССИИ` → `ИСТОРИЯ РОССИИ`).
      Обрезаются пробелы, запятые и `/` по краям; точка в конце сокращения
      (`ОРГ.`) сохраняется. Регистр и опечатки на этом этапе **не трогаются**:
      это задача `normalize`. Пусто → `discipline = None`.

`clean` никогда не бросает исключение. Строка, которую не удалось разобрать,
даёт занятие с пустыми полями и флагом `needs_review`.

## Нормализация (`normalize.py`)

- **Ключ дисциплины** `disc_key`: `casefold`, `ё→е`, схлопнутые пробелы,
  без пунктуации по краям. Сравнение в тестах `clean` — тоже по ключу.
- **Дисциплины**: кластеризация `rapidfuzz.fuzz.ratio ≥ 85` по ключу.
  Канон кластера — самый частый вариант, при равенстве — вариант не капсом.
  Каждая склейка с `score < 100` пишется в `merges`. Так закрываются
  опечатки (`Иностанный`), а сокращения (`Стратегич.`, `недвиж-ти`)
  склеиваются, если хватает похожести; несклеенные видны на странице
  качества.
- **Преподаватели**: `Фамилия` без инициалов присоединяется к
  `Фамилия И.О.`, если в снапшоте ровно одно полное ФИО с такой фамилией;
  иначе остаётся отдельной записью с флагом `teacher_surname_only`.
  Это основной, а не редкий путь: так записано около 16% строк.
  Fuzzy по фамилиям — порог 90.
- **Аудитории**: литера приклеивается (`431 а` → `431а`), латинская `C` в
  `С-` заменяется кириллической. Аудитория уникальна в паре
  (корпус, номер): если корпуса в тексте нет, берётся корпус из иерархии
  парсера (`uk1`/`uk2`/`uk3` → `УК1`/`УК2`/`УК3`). У мест из справочника
  с корпусом `Прилегающие здания` корпус из иерархии не применяется;
  именованные лаборатории получают корпус из иерархии.

## Флаги качества

| флаг | условие |
|---|---|
| `has_type` / `has_discipline` / `has_teacher` / `has_room` | поле распознано |
| `discipline_fuzzy` | дисциплина получена fuzzy-склейкой |
| `teacher_surname_only` | хотя бы один преподаватель остался без инициалов |
| `split_cell` | занятие получено разрезанием ячейки на несколько |
| `suspicious_group` | имя группы без цифр или короче 3 символов |
| `needs_review` | нет дисциплины, **или** нет преподавателя, **или** нет аудитории, **или** подозрительная группа |

Отдельная проверка снапшота: у группы больше 6 учебных дней или дни идут не
по порядку — предупреждение о возможном сдвиге дней недели.

## Тестирование

TDD, `pytest`. Приоритет — слой очистки.

- `test_clean.py` — параметризован по `fixtures/subject_cases.json`
  (70 реальных строк, 36 категорий). Режим `strict`: список занятий
  сравнивается целиком — тип, дисциплина по `disc_key`, преподаватели и
  аудитории как упорядоченные списки в каноне, корпус, подгруппа, признак
  служебной строки. Режим `flags`: проверяются только флаги (обрезанные
  ячейки). Плюс пустая строка и строка из одних пробелов.
- `test_clean_corpus.py` — прогон всех 4005 строк корпуса: `clean` ни разу
  не бросает исключение; доли распознанных полей (тип, дисциплина,
  преподаватель, аудитория) не ниже порогов. Пороги фиксируются по факту
  после реализации (замеренное значение минус 1 п.п.) и защищают от регрессий.
- `test_normalize.py` — склейка опечаток («сорт»/«спорт», «Иностанный»), отказ склеивать
  разные дисциплины, присоединение фамилии к полному ФИО и отказ при
  неоднозначности.
- `test_flatten.py` — число строк, сохранение иерархии, `week` → `week_type`.
- `test_load.py` — ETL на фикстуре в БД во временном файле, идемпотентность.
- `test_analytics.py` — недельная нагрузка с 0.5 и с `1/n` для разрезанных
  ячеек, служебные строки не входят в нагрузку, матрица кабинет×дисциплина,
  одинаковый номер аудитории в разных корпусах — разные аудитории,
  применение фильтров.
- `test_smoke.py` — `streamlit.testing.AppTest` прогоняет каждую страницу на
  фикстурной БД без исключений.

Проверка в Docker: `docker compose up --build`, стенд открывается, кнопка
сбора создаёт новый снапшот.

## Известные ограничения апстрим-парсера

Описываются в README, стенд их подсвечивает:

1. Дни недели назначаются позиционно по сбросу времени — пропущенный день
   сдвигает метки.
2. Заголовок групп в одной ячейке режется по пробелу (`1 бэ` → `1`, `бэ`).
3. Каждый запрос — полный обход сайта и перекачка всех PDF (минуты).
4. `pdfplumber` склеивает объединённые ячейки PDF: в одной строке `subject`
   оказываются несколько занятий (около 5%), а капсовое название лекции
   повторяется по числу групп. Решается разрезанием в `clean`; неделю
   каждого куска восстановить нельзя — отсюда `week_factor = 1/n`.
5. Часть ячеек приходит с оборванным началом или без дисциплины (около 2–3%).
6. На сайте есть битые ссылки на PDF (5 из 204 на 2026-10-07): парсер
   пишет предупреждение в лог и пропускает их.

## Вне рамок

- Модификация парсера.
- Авторизация, многопользовательский режим, деплой в интернет.
- Расписание экзаменов и заочников с нестандартной сеткой — грузится как
  есть, отдельно не обрабатывается.
