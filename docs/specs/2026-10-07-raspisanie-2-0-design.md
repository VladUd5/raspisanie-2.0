# Расписание 2.0 — дизайн лабораторного стенда

Дата: 2026-10-07
Статус: согласован с заказчиком; уточнён по черновой реализации (182 теста, живой прогон парсера и `docker compose`, проверка страниц скриншотами); нормализация переделана под проверенный словарь написаний — см. [2026-10-07-slovar-napisanij-design.md](2026-10-07-slovar-napisanij-design.md)

## Цель

Лабораторный стенд, который показывает сквозной цикл обработки данных
**сбор → очистка → анализ** на примере расписания Вавиловского университета.
Студенты работают со стендом интерактивно: переключают страницы, ставят
фильтры, смотрят таблицы и графики, выгружают результаты.

Источник требований — файл `ТЗ` в корне репозитория.

## Принятые решения

| вопрос | решение |
|---|---|
| платформа стенда | Python + Streamlit, хранилище SQLite, графики Plotly |
| источник данных | кнопка «Собрать данные» (живой парсинг) + демо-снапшот в репозитории |
| парсер | `mbfuss/smart_schedule_parser` подключён git submodule и **не модифицируется**; вся очистка — в нашем ETL |
| запуск | `docker compose up`, стенд на `http://localhost:8501` |
| документация | собственный `README.md` на русском |

## Исходные данные: что реально отдаёт парсер

`GET /getschedule?urlSchedule=www.vavilovsar.ru/ucheba/raspisanie-zanyatii`
возвращает массив корпусов:

```
Building{name, institutes[]}
  Institute{name, forms[]}
    StudyForm{name, groups[]}
      Group{name, schedule{days[]}}
        Day{name, lessons[]}
          Lesson{time_from, time_to, subject, week?}
```

- `name` корпуса/института/формы — slug из URL (`uk1`, `institut-agrobiznesa`,
  `ochnaya-forma-obucheniya`).
- `week` отсутствует → занятие на обеих неделях; иначе `numerator` / `denominator`.
- Поля `Lecturer` и `Room` в апстриме закомментированы. **`subject` содержит
  весь текст ячейки PDF**: тип занятия, дисциплину, преподавателя(ей),
  аудиторию(и), а также опечатки источника. Примеры из реального PDF:

```
лек. ИСТОРИЯ МИРОВОЙ КУЛЬТУРЫ ст.пр. Аленичева Н.В. 314
пр.з. Физическая культура и сорт Кузьмин 422
пр.з .Иностанный язык Раздобарова, Бормосова 450, 528
Экономическая культура доц. Васильева Е.А. (5 лек.), Ерзова (5 пр.з.) 232
лек. ТЕОРИЯ СИСТЕМ И СИСТЕМНЫЙ АНАЛИЗ доц. Косарев А.А. 134 к
```

Следствие: отчёты по преподавателям и аудиториям из ТЗ невозможны без
стадии очистки. Это центральная часть стенда.

## Архитектура

```
[vavilovsar.ru] --PDF--> parser (Go, :8080)
                              │ JSON                       СБОР
                              ▼
                 data/snapshots/<YYYY-MM-DD_HHMMSS>.json
                              │                            ОЧИСТКА
                              ▼
  flatten → clean → canon (словарь → normalize) → load (SQLite data/schedule.db)
                              │                            АНАЛИЗ
                              ▼
                     stand (Streamlit, :8501)
```

Два сервиса в `docker-compose.yml`:

- `parser` — сборка из `vendor/smart_schedule_parser` его собственным
  `docker/Dockerfile`; при старте `HOST` в `.env` подменяется на `0.0.0.0`
  (как в апстрим-compose). Порт наружу не обязателен.
- `stand` — Python 3.10 + Streamlit. Обращается к парсеру по
  `PARSER_URL=http://parser:8080`. Том `./data` смонтирован в контейнер.

Без Docker стенд запускается локально (`streamlit run stand/app.py`) на
демо-снапшоте; кнопка сбора в этом режиме сообщает, что парсер недоступен.

### Компоненты

| модуль | ответственность | вход → выход |
|---|---|---|
| `etl/collect.py` | HTTP-запрос к парсеру, сохранение снапшота | URL → путь к `.json` |
| `etl/flatten.py` | разворот вложенного JSON в плоские строки | JSON → `list[RawLesson]` |
| `etl/clean.py` | разбор `subject`: отсев служебного, разрезание на занятия, поля | `str` → `ParsedCell` |
| `etl/locations.py` | справочник словесных аудиторий (прилегающие здания, именованные лаборатории) | — (данные: регулярка → аудитория, корпус) |
| `etl/dictionary.py`, `etl/dictionary/*.csv` | проверенный вручную словарь написаний | CSV → `Dictionary` |
| `etl/normalize.py` | автоправила для непроверенных написаний: fuzzy-дедуп дисциплин, ФИО, имена групп | список имён → маппинг вариант→канон + журнал |
| `etl/canon.py` | канон каждого написания: словарь → автоправила → как есть; сверка правил со словарём | разобранные занятия → `Resolved` |
| `etl/variants.py` | вид ошибки написания и посимвольная разница | (написание, канон) → виды, отрезки |
| `etl/audit.py` | сверка склеек по парам написаний | два маппинга → верные/ложные/пропущенные |
| `etl/load.py` | оркестрация ETL и запись в SQLite | снапшот → `snapshot_id` |
| `analytics/queries.py` | агрегаты для отчётов (чистые функции над DataFrame) | DataFrame + фильтры → DataFrame |
| `charts/common.py` | построители фигур Plotly, проверенная палитра | DataFrame → Figure |
| `labels.py` | человекочитаемые названия slug-ов, дней, недель, колонок | — |
| `ui/*.py` | кэш чтения БД, сквозные фильтры, тема, HTML карточек словаря | — |
| `app.py`, `views/*.py` | UI: `st.navigation` с разделами «Расписание» и «Аналитика», сайдбар-фильтры и 9 страниц | — |

Модули ETL и аналитики не импортируют Streamlit — тестируются отдельно.

## Модель данных (SQLite)

```
snapshots(id PK, collected_at, source_url, file_name,
          groups_cnt, cells_cnt, lessons_cnt, service_cnt)

cells(id PK, snapshot_id FK,               -- одна ячейка PDF = одна строка subject
      building, institute, study_form, group_name,
      day, day_idx, time_from, time_to, duration_h,
      week_type,                           -- both | numerator | denominator (из парсера)
      subject_raw,
      is_service,                          -- служебная строка, занятий не порождает
      truncated,                           -- ячейка с оборванным началом
      lessons_in_cell)                     -- сколько занятий получилось после разрезания

lessons(id PK, cell_id FK, snapshot_id FK,
        part_idx,                          -- номер занятия внутри ячейки
        lesson_type,   -- лекция | практика | лабораторная | семинар | консультация | зачёт | экзамен | не определён
        discipline_id FK NULL,
        subgroup NULL,                     -- 1, 2, … ; NULL = вся группа
        building,                          -- корпус из текста (УК2, ФТИК) или корпус из иерархии парсера
        week_factor)

disciplines(id PK, snapshot_id FK, name)                    -- каноническое название
discipline_aliases(snapshot_id FK, alias, discipline_id FK)  -- варианты написания

teachers(id PK, snapshot_id FK, full_name, surname)
lesson_teachers(lesson_id FK, teacher_id FK)

rooms(id PK, snapshot_id FK, building, name)  -- аудитория уникальна в паре (корпус, номер)
lesson_rooms(lesson_id FK, room_id FK)

quality(lesson_id PK FK, has_type, has_discipline, has_teacher, has_room,
        discipline_fuzzy, teacher_surname_only, split_cell,
        suspicious_group, truncated, needs_review, unverified_name)

spellings(snapshot_id, kind, spelling, canonical,   -- каждое написание и его канон
          source, confidence, error_kinds, note, lessons, score)
rule_audit(snapshot_id, kind, tp, fp, fn)           -- сверка автоправил со словарём
```

`kind` в `spellings`: `discipline | teacher | room | group | lesson_type`;
`source`: `словарь | словарь? | правило | как есть | разбор`. Версия схемы —
`PRAGMA user_version`; при несовпадении стенд пересоздаёт БД и перечитывает
снапшоты из `data/snapshots`.

Справочники (дисциплины, преподаватели, аудитории) строятся заново для
каждого снапшота: канон берётся из проверенного словаря, а для написаний,
которых в словаре нет, — из автоправил, которые зависят от состава снапшота.
Повторный ETL того же снапшота заменяет его данные (идемпотентность).
Служебные строки сохраняются в `cells` (для страницы качества), но занятий
не порождают и в нагрузку не входят.

### Счёт нагрузки

- `duration_h = time_to − time_from` в часах (пара 1.5 ч).
- `week_factor = 0.5` для числителя/знаменателя, `1.0` для обеих недель.
- Недельная нагрузка = Σ `duration_h × week_factor`.
- Переключатель в сайдбаре «считать числитель/знаменатель полной парой»
  заменяет `week_factor` на 1.0.
- Занятие с несколькими преподавателями засчитывается каждому полностью;
  с несколькими аудиториями — каждой аудитории полностью.
- **Занятость слота не больше одной пары.** У преподавателя и аудитории
  сумма по слоту (кто/где, день, время начала) не превышает 1 пару в неделю:
  числитель + знаменатель = 1, а наложения (ошибки расписания, сессии
  заочников в «тот же» день) срезаются пропорционально. Без этого на
  реальных данных у аудитории выходило 90 ч/нед при физическом максимуме
  ≈54 (36 слотов × 1.5 ч). Переключатель «полной парой» этот потолок не
  отменяет.
- **Поточная лекция.** Парсер повторяет лекцию для нескольких групп в
  ячейке каждой группы. Поэтому нагрузка преподавателя и аудитории считается
  по уникальным **событиям**: одинаковые (преподаватель или аудитория, день,
  время начала, тип недели, тип занятия, дисциплина) — одно событие. Для
  дисциплины событие различается ещё и составом преподавателей (лабораторные
  подгрупп у разных преподавателей — разные события). Число групп при этом
  считается по всем ячейкам.
- **Разрезанная ячейка.** Если из одной ячейки получилось `n > 1` занятий,
  а парсер считает её занятием на обе недели, то это, скорее всего,
  чередование (числитель/знаменатель или подгруппы склеились при конвертации
  PDF). Каждое занятие получает `week_factor = 1/n` и флаг `split_cell`.
  Если у ячейки уже есть числитель/знаменатель — `0.5/n`.
- Переключатель «считать числитель/знаменатель полной парой» ставит
  `week_factor = 1.0` всем занятиям, включая разрезанные.

## Правила очистки (`clean.py`)

Вход — одна строка `subject` (одна ячейка PDF). Выход:

```
ParsedCell(is_service: bool, lessons: list[ParsedLesson])
ParsedLesson(lesson_type, discipline | None, teachers: list[str],
             rooms: list[str], building | None, subgroup | None)
```

Конвейер (порядок важен):

1. **Предобработка.** `\n` → пробел, схлопывание пробелов, `trim`.
   Схлопывание разрядки: 3+ одиночные заглавные буквы через одиночный пробел
   склеиваются (`С К О Т О В О Д С Т В О` → `СКОТОВОДСТВО`,
   `А С У Т П` → `АСУТП`, `п е р е е з д` → `переезд`).
2. **Служебные фрагменты.** Вырезаются `переход на УК N`, `переезд( на УК N)?`,
   `(Единый) кураторский час`, `*`. Если после этого не осталось ни одной буквы —
   ячейка служебная: `is_service = true`, `lessons = []`.
3. **Аннотации часов, время и звания** вырезаются до поиска типов, чтобы не
   создать ложное занятие и ложную аудиторию: `N лек. + M пр.`, `(N лек.)`,
   `(N пр.з.)`, `(N)` после фамилии, `с 13.40`. Звания (`доц.`, `доцент`,
   `проф.`, `проф`, `профессор`, `ст. пр.`, `ст.пр.`, `ст.преп.`, `преп.`,
   `асс.`, в том числе слитно с фамилией) вырезаются здесь же: иначе «пр.» из
   «ст. пр.» был бы принят за маркер практики. `доц`/`проф` без точки
   вырезаются только как отдельное слово («профессия» не трогается).
   Ячейка, начинающаяся со строчной буквы не с маркера типа, помечается
   `truncated` (оборванное начало).
4. **Места в прилегающих зданиях** распознаются по справочнику
   `etl/locations.py` **до** разрезания и заменяются плейсхолдером. Иначе
   `лаб. Акуш.` в конце строки будет принят за маркер второго лабораторного
   занятия. Каждая запись справочника — **отдельная аудитория** со своим
   корпусом. Справочник на старте:

   | шаблон в тексте | аудитория | корпус |
   |---|---|---|
   | `физ. зал`, `физ.зал`, `(физ. зал)` | Физ. зал | Прилегающие здания |
   | `сок` (отдельным словом) | СОК | Прилегающие здания |
   | `каф.ФиС`, `каф. ФиС`, `.каф. ФиС`, `КФиС` | Кафедра ФиС | Прилегающие здания |
   | `каф. Терап.` | Кафедра терапии | Прилегающие здания |
   | `кванториум`, `Кванториум` | Кванториум | Прилегающие здания |
   | `АГРОЦЕНТР, корпус ФТИК, ауд. N.` | Агроцентр ФТИК, ауд. N | Прилегающие здания |
   | `лаб. Акуш.` | Лаб. акушерства | корпус института |
   | `лаб.Эпизоотологии`, `лаб. Эпизоот.` | Лаб. эпизоотологии | корпус института |
   | `лаб. Паразитологии` | Лаб. паразитологии | корпус института |
   | `лаб.Патанат`, `лаб.Пат.Анат.` | Лаб. патанатомии | корпус института |
   | `лаб.анатомии`, `лаб.Анатомии` | Лаб. анатомии | корпус института |
   | `лаб.Ин-яз`, `лаб.ин.` | Лаб. иностранных языков | корпус института |
   | `лаб.терап.` | Лаб. терапии | корпус института |
   | `лаб.морф.` | Лаб. морфологии | корпус института |

   Шаблоны лабораторий регистронезависимы (`лаб.акуш.` = `лаб. Акуш.`).

   «Прилегающие здания» — групповая метка корпуса для фильтра, а не одно
   место: Физ. зал, СОК и Кванториум остаются разными аудиториями.
   «Корпус института» — корпус из иерархии парсера; все именованные
   лаборатории встречаются только в расписаниях институтов УК3, как и
   `ауд. Большая` / `ауд. Малая`.

   Справочник — обычный Python-список «регулярка → название, корпус».
   Пополнять его можно без правки логики. Строки, где после ФИО остался
   нераспознанный хвост без цифр, попадают на страницу качества: так
   находятся новые места.
5. **Разрезание на занятия.** Маркер типа занятия (регистронезависимо, точка и
   пробел внутри опциональны):

   | маркер | тип |
   |---|---|
   | `лек` | лекция |
   | `пр.з`, `пр з`, `пр. з`, `пр.з .`, `пр.` (без «з») | практика |
   | `лаб.з`, `лаб. з`, `лаб.`, `лб.з` | лабораторная |
   | `сем` | семинар |
   | `конс` | консультация |
   | `ЗАЧЕТ`, `зачёт` | зачёт |
   | `ЭКЗАМЕН` | экзамен |

   Маркер — отдельное слово: не предварён буквой, цифрой, `(`, `.`, `-`;
   маркер без точки не продолжается буквой (`ЛЕКАРСТВЕННЫЕ`, `СЕМЕНОВОДСТВО`
   — не маркеры). `лаб.`/`пр.` без «з» не считаются маркером, если сразу за
   точкой строчная буква (`Лаб.диагност.` — дисциплина). «Семинар» и
   «консультация» распознаются только в начале строки (`сем. посевов`).
   Строка режется перед каждым маркером, кроме первого; пустые куски
   (`лек. лек.`) отбрасываются. Текст до первого маркера: если в нём есть ФИО
   с инициалами или аудитория — это отдельное занятие типа «не определён»,
   иначе (`2-я подгруппа …`) он присоединяется к первому занятию. Нет ни
   одного маркера — одно занятие с типом «не определён».
6. **Внутри каждого занятия:**
   1. **Подгруппа**: `Nп/г`, `N п/г`, `N-я подгруппа`, `N подгруппа` →
      `subgroup = N`, фрагмент вырезается.
   2. **Корпус**: `УК N`, `(УК N)`, `УК №N`, `УКN` → `building = "УКN"`;
      `корпус X` → `building = "X"`. Фрагмент вырезается вместе с
      предшествующими словами-локациями в капсе (`АГРОЦЕНТР,`).
   3. **Аудитории**, в любом месте строки:
      - `ауд. N`, `ауд.N`, `ауд .N` — N из 1–4 цифр с необязательной литерой;
      - `С-N`, `Х-N` (буквенный корпус) — сохраняется как есть, латинские
        `C`/`X` заменяются кириллическими;
      - отдельное число из 3–4 цифр с необязательной литерой (`518а`,
        `431 а` → `431а`), не входящее в ФИО и не являющееся частью времени;
      - двузначное число в самом конце строки (`Демин Е.Е.33`,
        `Васильчиков В.В. 40`) — в корпусе 39 таких строк, это аудитории;
      - именованные: `ауд. Большая`, `ауд. Малая` → `Большая`, `Малая`
        (аудитории основного корпуса института);
      - места из справочника (шаг 4) — с корпусом из справочника;
      - разделители между несколькими аудиториями — `,`, `/`, пробел.
      Порядок аудиторий — как в строке.
   4. **Преподаватели с инициалами**: `Фамилия И.О.`, `Фамилия И. О.`,
      `Фамилия И.О` (без последней точки), `Фамилия ЕД.` (без точки между
      инициалами), `Фамилия О В.` (пробел вместо точки), `Фамилия Е.Н .`
      (оторвавшаяся точка), в том числе без пробела перед следующим ФИО
      (`Ю.С.Чернышев`) и перед номером аудитории (`Г.Е.131`). Канон:
      `Фамилия И.О.`
   5. **Преподаватели без инициалов**: слово с заглавной буквы (от 3 букв),
      которое не первое слово занятия и за которым идёт аудитория, конец
      строки или запятая перед другим преподавателем (`Воронова, Ларюков 316`).
      Без запятой цепочка не продолжается: в `История России Шалаева 422`
      «России» — часть дисциплины. Стоп-лист частых слов в конце названий
      дисциплин: России, Российской, Земли, Европы, Азии, Сибири, Поволжья, Мира.
   6. **Дисциплина** — то, что осталось между маркером типа и первым
      преподавателем или аудиторией. Повтор капсового названия схлопывается
      до одного (`ИСТОРИЯ РОССИИ ИСТОРИЯ РОССИИ` → `ИСТОРИЯ РОССИИ`).
      Обрезаются пробелы, запятые и `/` по краям; точка в конце сокращения
      (`ОРГ.`) сохраняется. Регистр и опечатки на этом этапе **не трогаются**:
      это задача `normalize`. Пусто → `discipline = None`.
      Разрядка многословного названия (`Б Е З О П А С Н О С Т Ь Ж И З Н Е …`)
      склеивает слова: в PDF между словами такой же одинарный пробел, как
      между буквами. Получается `БЕЗОПАСНОСТЬЖИЗНЕДЕЯТЕЛЬНОСТИ`; это чинит
      склейка в `normalize`.

`clean` никогда не бросает исключение. Строка, которую не удалось разобрать,
даёт занятие с пустыми полями и флагом `needs_review`.

Покрытие на корпусе из 4005 строк (черновая реализация, 2026-10-07): тип
97.2%, дисциплина 98.4%, преподаватель 97.7%, аудитория 95.7%.

## Нормализация (`canon.py`, `normalize.py`)

Канон каждого написания берётся сначала из проверенного вручную словаря
(`stand/etl/dictionary/*.csv`), затем из автоправил, иначе написание остаётся
каноном самого себя. Подробно — в
[2026-10-07-slovar-napisanij-design.md](2026-10-07-slovar-napisanij-design.md).
Ниже — автоправила для непроверенных написаний.

- **Ключ дисциплины** `disc_key`: `casefold`, `ё→е`, схлопнутые пробелы,
  без пунктуации по краям. Сравнение в тестах `clean` — тоже по ключу.
- **Дисциплины**: кластеризация `rapidfuzz.fuzz.ratio ≥ 80` по ключу,
  плюс два запрета склейки:
  - одно название целиком входит в другое (`органическая химия` ⊂
    `неорганическая химия`) или различаются числа (`Иностранный язык 1`/`2`);
  - пословная проверка: у каждого слова от 3 букв должна быть пара в другом
    названии — совпадение, сокращение-префикс (`технол.` / `технологии`),
    вхождение (слипшиеся слова от разрядки) или опечатка: одна правка
    (Левенштейн) в слове от 4 букв, две — только в слове от 9 букв с
    одинаковыми первыми двумя буквами. Так не склеиваются
    `Общая`/`Пищевая биотехнология`, `Эконометрика`/`Экономика`,
    `Геология`/`Экология`, `Почвоведение`/`Правоведение`, но склеиваются
    `Общая физ.подготовка` и `Общая физическая подготовка`.
  Канон кластера — вариант с наименьшим числом сокращений, затем не капсом,
  затем самый частый, затем самый длинный (опечатки чаще теряют буквы); капс
  приводится к виду предложения с сохранением коротких аббревиатур
  (`Инновационный менеджмент АПК`, но `… и охрана труда`), иначе первая
  буква — заглавная. Новое написание может присоединиться к кластеру словаря
  и получает его канон; обрезанное название присоединяется к единственному
  кластеру, чьё название с него начинается, при общем преподавателе; два слова
  из канонов словаря не считаются опечаткой друг друга; короткие аббревиатуры
  без точки должны совпадать (`в ЛА` ≠ `в ЛД`). Склейка с `score < 100`
  попадает в `spellings.score`. Итог на снапшоте 2026-10-07 (по словарю):
  2138 написаний → 996 дисциплин.
- **Преподаватели**: `Фамилия` без инициалов присоединяется к
  `Фамилия И.О.`, если в снапшоте ровно одно полное ФИО с такой фамилией;
  иначе остаётся отдельной записью с флагом `teacher_surname_only`.
  Это основной, а не редкий путь: так записано около 16% строк.
  **Опечатка в фамилии** — ровно одна правка (Левенштейн ≤ 1), та же первая
  буква, то же окончание (последние 2 буквы), длина от 5 букв. Так склеиваются
  `Тороппова В.В.`→`Торопова В.В.`, но не `Газизов`/`Азизов`,
  `Иванов`/`Иванова`, `Ким`/`Кин`. Полные ФИО склеиваются по этому правилу
  при одинаковых инициалах; при общей дисциплине — также инициалы, отличающиеся
  одной буквой или переставленные (`Козлов С.Е.`→`Козлов Е.С.`), и родовое
  окончание (`Березкина А.С.`→`Березкин А.С.`). Фамилия без инициалов — к
  единственному полному ФИО, а при нескольких — к единственному с общей
  дисциплиной. Итог на снапшоте 2026-10-07 (по словарю): 677 написаний →
  476 преподавателей.
- **Группы**: пробелы вокруг дефиса схлопываются (`ВТ -404` → `ВТ-404`).
- **Аудитории**: литера приклеивается (`431 а` → `431а`), латинская `C` в
  `С-` заменяется кириллической. Аудитория уникальна в паре
  (корпус, номер): если корпуса в тексте нет, берётся корпус из иерархии
  парсера (`uk1`/`uk2`/`uk3` → `УК1`/`УК2`/`УК3`). У мест из справочника
  с корпусом `Прилегающие здания` корпус из иерархии не применяется;
  именованные лаборатории получают корпус из иерархии.

## Флаги качества

| флаг | условие |
|---|---|
| `has_type` / `has_discipline` / `has_teacher` / `has_room` | поле распознано |
| `discipline_fuzzy` | дисциплина склеена автоправилом (не словарём) со `score < 100` |
| `teacher_surname_only` | хотя бы один преподаватель остался без инициалов |
| `split_cell` | занятие получено разрезанием ячейки на несколько |
| `suspicious_group` | имя группы без цифр или короче 3 символов |
| `truncated` | ячейка начинается со строчной буквы не с маркера типа (оборванное начало) |
| `unverified_name` | дисциплина или преподаватель с источником `правило` или `как есть` (нет в словаре) |
| `needs_review` | нет дисциплины, **или** нет преподавателя, **или** нет аудитории, **или** подозрительная группа, **или** оборванная ячейка |

Отдельная проверка снапшота: у группы есть занятия в воскресенье —
предупреждение о возможном сдвиге дней недели (парсер называет дни по
порядку, «лишний» день уезжает в воскресенье).

## Страницы стенда

Сквозные фильтры в сайдбаре (на всех страницах): снапшот, корпус, институт,
форма обучения, группа, день недели, тип недели, тип занятия, переключатель
счёта числителя/знаменателя. **По умолчанию выбрана очная форма**: у
заочной и очно-заочной расписание сессионное, и их «неделя» несопоставима
с неделей очников. «Сбросить фильтры» возвращает к этому умолчанию.

Страницы лежат в `stand/views/`, а не в `stand/pages/`: папку `pages/` рядом
с точкой входа Streamlit подхватывает сам, и прямая ссылка на страницу
открывает её без `app.py` (без фильтров).

Меню разбито на два раздела: «Расписание» (страницы 1–5 и «Данные и экспорт»)
и «Аналитика» (инфографика, качество данных, словарь написаний). Рейтинги на
страницах 2–5 переключаются между «самые загруженные» и «наименее
загруженные» — внизу рейтинга видны выбросы.

| # | страница | таблицы | графики | пункт ТЗ |
|---|---|---|---|---|
| 1 | Обзор и пайплайн | история снапшотов, счётчики | схема этапов, занятия по институтам | демонстрация цикла; кнопка «Собрать данные» |
| 2 | Преподаватели | часы, пар, дисциплин, групп, аудиторий по каждому | топ-N по часам; теплокарта день×время выбранного; типы занятий | загруженность преподавателя на неделю; занятия независимо от профиля |

| 5 | Группы | пары в неделю по группам (сводка по формам обучения); сетка день×слот выбранной группы | рейтинг групп по парам; нагрузка по дням | — |

| 7 | Качество данных | проблемные строки с `subject_raw` и результатом разбора, наложения в расписании преподавателей (кроме разрезанных ячеек), служебные строки | доли распознанных полей; доли по флагам | показ стадии очистки |
| 8 | Словарь написаний | карточки «канон → написания» с подсвеченной разницей и видом ошибки; сверка автоправил со словарём; все написания с выгрузкой CSV | занятия с ошибкой в написании по видам | показ стадии очистки |
| 9 | Данные и экспорт | все занятия с фильтрами | — | выгрузка CSV и XLSX |

Графики: Plotly, палитра, проверенная на различимость (в том числе для дальтоников), в светлой
и тёмной теме (категориальные слоты 1–7 закреплены за типами занятий, «не
определён» — нейтральный серый; магнитуда — одноцветная синяя шкала).
Рейтинги — одна серия одним цветом без легенды; стек по типам — с легендой.
У каждого графика на странице есть таблица с теми же числами (в светлой теме
три цвета ниже 3:1 к фону, таблица — обязательная замена).

Сценарий кнопки «Собрать данные»: запрос к парсеру с таймаутом 15 минут и
спиннером → сохранение снапшота → ETL → выбор нового снапшота в фильтре.
Ошибка парсера или таймаут показываются сообщением; прежние снапшоты
остаются доступными.

При первом старте, если БД пуста, ETL автоматически прогоняется по всем
снапшотам из `data/snapshots/`.

## Тестирование

TDD, `pytest`. Приоритет — слой очистки.

- `test_clean.py` — параметризован по `fixtures/subject_cases.json`
  (113 реальных строк). Режим `strict`: список занятий
  сравнивается целиком — тип, дисциплина по `disc_key`, преподаватели и
  аудитории как упорядоченные списки в каноне, корпус, подгруппа, признак
  служебной строки. Режим `flags`: проверяются только флаги (обрезанные
  ячейки). Плюс пустая строка и строка из одних пробелов.
- `test_clean_corpus.py` — прогон всех 4005 строк корпуса: `clean` ни разу
  не бросает исключение; доли распознанных полей (тип, дисциплина,
  преподаватель, аудитория) не ниже порогов. Пороги фиксируются по факту
  после реализации (замеренное значение минус 1 п.п.) и защищают от регрессий.
- `test_normalize.py` — склейка опечаток («сорт»/«спорт», «Иностанный»), отказ склеивать
  разные дисциплины, присоединение фамилии к полному ФИО и отказ при
  неоднозначности.
- `test_variants.py`, `test_audit.py`, `test_dictionary.py`, `test_canon.py` —
  вид ошибки на реальных примерах, сверка по парам, чтение и проверка словаря
  (в том числе BOM, разделитель `;`, дубли), порядок «словарь → правила → как
  есть», правила преподавателей с общей дисциплиной и отказы.
- `test_flatten.py` — число строк, сохранение иерархии, `week` → `week_type`.
- `test_load.py` — ETL на фикстуре в БД во временном файле, идемпотентность.
- `test_analytics.py` — недельная нагрузка с 0.5 и с `1/n` для разрезанных
  ячеек, служебные строки не входят в нагрузку, матрица кабинет×дисциплина,
  одинаковый номер аудитории в разных корпусах — разные аудитории,
  применение фильтров.
- `test_collect.py` — сохранение снапшота и понятные ошибки (парсер
  недоступен, таймаут, HTTP 500, не JSON, пустой ответ) без мусора на диске.
- `test_charts.py` — цвета закреплены за типами, рейтинг без легенды, стек в
  фиксированном порядке типов.
- `test_smoke.py` — `streamlit.testing.AppTest`: каждая из 9 страниц на
  фикстурной БД без исключений; пустая БД — подсказка; сбор без парсера —

Проверка в Docker: `docker compose up --build`, стенд открывается, кнопка

Время сбора сохраняется со смещением пояса (`2026-10-07T12:03:39+03:00`;
в контейнере — UTC), снапшоты сортируются по разобранному времени.
Имя проекта Compose задано явно (`name: raspisanie`): из имени папки
«Расписание 2.0» Compose молча выводит имя «20».

## Известные ограничения апстрим-парсера

Описываются в README, стенд их подсвечивает:

1. Дни недели назначаются позиционно по сбросу времени — пропущенный день
   сдвигает метки.
2. Заголовок групп в одной ячейке режется по пробелу (`1 бэ` → `1`, `бэ`).
3. Каждый запрос — полный обход сайта и перекачка всех PDF (минуты).
4. `pdfplumber` склеивает объединённые ячейки PDF: в одной строке `subject`
   оказываются несколько занятий (около 5%), а капсовое название лекции
   повторяется по числу групп. Решается разрезанием в `clean`; неделю
   каждого куска восстановить нельзя — отсюда `week_factor = 1/n`.
5. Часть ячеек приходит с оборванным началом или без дисциплины (около 2–3%).
6. На сайте есть битые ссылки на PDF (5 из 204 на 2026-10-07): парсер
   пишет предупреждение в лог и пропускает их.

## Вне рамок

- Модификация парсера.
- Авторизация, многопользовательский режим, деплой в интернет.
- Расписание экзаменов и заочников с нестандартной сеткой — грузится как
  есть, отдельно не обрабатывается.
