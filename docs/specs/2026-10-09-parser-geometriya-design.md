# Разбор PDF по геометрии сетки — дизайн

Дата: 2026-10-09
Статус: реализовано в ветках `parser-geometriya` (стенд) и `geometriya` (сабмодуль, локально); ждёт просмотра заказчиком
Основа: [дизайн стенда](2026-10-07-raspisanie-2-0-design.md), [словарь написаний](2026-10-07-slovar-napisanij-design.md)

## Цель

Парсер (`vendor/smart_schedule_parser`, Go + Python-скрипт на pdfplumber) теряет и
переставляет данные ещё до стенда. Ошибки разбора задевают всё, что стенд строит
дальше: группы, дисциплины, преподавателей, аудитории, нагрузку. Их нужно
исправить в самом парсере, по причине, а не латками в стенде.

## Что найдено

Сверка группы без имени с PDF на сайте («1 курс М-ПИ-101.pdf», побайтно совпадает
с файлом, который скачал парсер) и разбор геометрии всех 199 PDF снапшота показали
одну общую причину. Скрипт превращает таблицу в CSV через `extract_tables()`, а
pdfplumber строит сетку **по краям всех прямоугольников**, включая белые
прямоугольники фона. Видимые линии во всех 199 PDF — тонкие тёмные прямоугольники
(в 12 файлах ещё и линии). Фон режет ячейки там, где на листе линии нет, и
CSV теряет связь текста с настоящей ячейкой.

| класс | пример | масштаб |
|---|---|---|
| пустое имя группы | между строкой «Дни · Часы · М-ПИ-101» и первым временем — строка фона; Go берёт её за заголовок | 1 группа, все её 15 занятий |
| подпись времени в нижней подстроке пары | пара 15:20 — две подстроки (числитель/знаменатель), подпись посередине чуть ниже; верхняя подстрока остаётся без времени, Go относит её к **предыдущей** паре без недели | 161 ячейка в 21 PDF |
| одна ячейка разрезана фоном | «лаб.з. Big Data» и «Шибайкин…, 520, 533» — одна видимая ячейка пары 17:00; парсер выдаёт название на 15:20, преподавателя — отдельным занятием на 17:00 | входит в строку выше; в снапшоте 154 ячейки «преподаватель + аудитория без дисциплины» |
| заголовок группы через линию столбца | «Б-ЛА-101» заходит в столбец «Часы»: заголовки «ЧасБы-ЛА», «-101 Б-ЛД-101» → группы `Б-ЛА`, `-101` | 1 PDF |
| даты заочки выброшены | в ячейке дня повёрнутым текстом «Понедельник 28.09.2026» или отдельный столбец «Дата» («21 сентября»); парсер оставляет только день недели | 31 заочная группа встречается в снапшоте 2–4 раза (недели сессии вперемешку) |

Ограничения 4–5 из README («склеенные ячейки», «оборванное начало») тоже
порождены CSV-путём; после перехода проверяются сверкой.

## Принятые решения

| вопрос | решение |
|---|---|
| где живут правки | форк `VladUd5/smart_schedule_parser`; пока форка нет — ветка `geometriya` в сабмодуле локально, без отправки |
| подход | Python-скрипт раскладывает текст по **видимой** сетке и отдаёт готовые занятия JSON; Go только собирает их в прежнюю структуру |
| формат ответа | прежний JSON + два необязательных поля: `date` у дня, `source` у группы; старые снапшоты читаются как раньше |
| даты заочки | берутся из таблицы, не из имени файла (в именах опечатки: «с 28.06.2026» при датах 28.09) |
| стенд | у заочки фильтр «Неделя сессии»; если одна неделя группы пришла несколькими файлами — берётся свежий |
| проверка | независимая сверка выдачи с текстом PDF по всем файлам + сравнение со старым снапшотом; каждое расхождение просматривается вручную по картинке ячейки |
| словарь | новые написания после пересбора проверяются вручную и дописываются в CSV словаря |

## Архитектура

### `scripts/pdf2cells.py` (заменяет `pdf2csv.py`)

На каждой странице:

1. **Линии.** Видимые линии — `page.lines` и прямоугольники с тёмной заливкой или
   обводкой толщиной ≤ 2 pt (тёмный — средняя яркость < 0,5). Белые и цветные
   прямоугольники фона не учитываются.
2. **Атомарная сетка.** Все различные x видимых вертикалей и y видимых горизонталей
   (с допуском 1,5 pt) режут таблицу на атомарные клетки. Соседние клетки
   объединяются, если между ними нет видимого отрезка. Получаются **видимые ячейки**
   — ровно то, что видит человек на листе.
3. **Текст ячейки.** Слова (`extract_words`, горизонтальный текст) относятся к
   ячейке по центру слова; строки собираются сверху вниз и склеиваются пробелом.
   Повёрнутый текст (дни, даты) собирается из символов по столбикам; для дня и даты
   пробуются оба направления чтения, принимается то, где распознаётся день недели
   или дата.
4. **Столбцы.** Столбец времени — тот, где ячейки распознаются как интервал
   времени. Левее — служебные (день, дата). Правее — столбцы групп: заголовок
   группы — ближайшая непустая ячейка над первой парой, не накрывающая служебные
   столбцы (шапка «Расписание занятий…» их накрывает).
5. **Пары и недели.** Каждая ячейка столбца времени с интервалом задаёт пару
   (y-диапазон). Ячейка группы относится к паре, с которой перекрывается больше
   чем наполовину своей высоты; если ячейка накрывает несколько пар — к каждой
   (двойная пара). Внутри пары: ячейка во всю высоту — обе недели; в верхней
   половине — числитель, в нижней — знаменатель.
6. **Группы.** Ячейка, накрывающая столбцы нескольких групп (поточная лекция),
   даёт занятие каждой из них.
7. **День и дата.** Служебные ячейки слева, перекрывающиеся с парой, дают день недели
   и (если есть) дату. Нераспознанный день — предупреждение, а не догадка.

Вывод: `{"groups": [{"name", "days": [{"name", "date", "lessons": [{time_from, time_to, week, subject}]}]}], "warnings": [...]}`.
Предупреждения (ячейка вне пар, нераспознанный день, текст вне ячеек) идут в
stderr и в отчёт сверки.

### Go

`ParsePDF` вызывает новый скрипт и переводит JSON в `[]resource.Group`. Код
CSV-пути (`detectLayout`, `buildGroups`, `parseTableToGroups`, `parseWeekType` и
их тесты) удаляется. `resource.Day` получает `Date string \`json:"date,omitempty"\``,
`resource.Group` — `Source string \`json:"source,omitempty"\`` (имя файла; префикс —
время загрузки на сайт). Обход сайта и провайдер не меняются.

### Стенд

- `flatten` переносит `date` дня и `source` группы в ячейку; таблица `cells`
  получает столбцы `date`, `source` (миграция `ALTER TABLE` при старте).
- Неделя сессии = понедельник недели, в которую попадает дата. Для одной группы и
  одной недели остаются ячейки только из файла с наибольшим префиксом `source`.
- Боковая панель: при выборе только заочной формы — фильтр «Неделя сессии»
  (по умолчанию последняя); в таблицах рядом с днём — дата.
- Снапшоты без дат работают как раньше.

## Проверка

1. **Тесты скрипта** (pytest, реальные PDF в `test/pdf`): М-ПИ-101 (имя, «русский
   язык» в 15:20 числителем, Big Data одной ячейкой в 17:00), «Б-ЛД-101» (две
   группы, правильные имена), заочный PDF с датами в ячейке дня и с отдельным
   столбцом «Дата».
2. **Тесты Go**: перевод JSON → группы, поля `date`/`source`.
3. **Сверка по всем PDF** (`tools/parser_audit.py` в репозитории стенда):
   - *полнота* — каждое слово в теле таблицы есть ровно в тех занятиях, чьи
     ячейки его содержат (потерянный и задвоенный текст);
   - *независимое время* — слово через `pdftotext -bbox` (poppler, другая
     библиотека) относится к паре по видимым линиям столбца времени; расхождение
     с выдачей — в отчёт;
   - *разница со старым снапшотом* по (группа, день, время, неделя, текст).
   Каждое расхождение просматривается вручную по вырезанной картинке ячейки и
   записывается как исправление или ошибка нового парсера.
4. **Пересбор**: обход сайта новым парсером, загрузка снапшота в стенд, ручная
   проверка новых написаний, тесты стенда.

## Вне рамок

- Разбор текста ячейки (дисциплина, преподаватель, аудитория) — остаётся в стенде.
- Расписание экзаменов и PDF с другой сеткой (если найдутся) — в отчёт, без поддержки.
- Отправка в форк и PR авторам — после просмотра заказчиком.

## Итоги (2026-10-09)

Сверка на одном корпусе (199 PDF снапшота 2026-10-07; старый парсер прогнан на нём же и дал те
же 5911 занятий, что в снапшоте). Каждое расхождение просмотрено по картинке ячейки.

Ошибки старого парсера, которых в новом нет:

| класс | пример |
|---|---|
| пустая полоса фона под шапкой → группа без имени | М-ПИ-101 |
| подпись времени в нижней половине пары → верхняя половина уходит на предыдущую пару | 161 ячейка в 21 PDF |
| одна ячейка разрезана фоном → название и преподаватель — разные занятия | лаб. Big Data |
| пунктир между верхней и нижней неделей не виден → «обе недели» | 122 занятия |
| смена дня по «время пошло назад» → опечатка в подписи сдвигает все следующие дни | «3 курс Б АА» |
| поточное занятие теряется у всех групп, кроме первой | 536 занятий, ВТ-102 и др. |
| несколько занятий и текст соседней группы в одной строке | «1 курс БЭ» |
| сдвиг столбца при пустой соседней группе | М-ЗиК-УЗК-101 → М-АА-101 |
| целые группы без занятий | Б-ЭиЭ-201, Б-ГМ-201, Б-СТв-101/201, Б-ЗК-52/53 |
| скрытая надпись в шапке → фантомные группы | «Б-ЛА», «-101» |

Ошибки, найденные и исправленные по ходу в новом разборе: слитые ячейки дней, текст в
разрядку, строка шире ячейки (крайние буквы и фантом у соседа), склейка текста соседних
ячеек, скрытый текст, перенос строки поверх соседней ячейки, занятие в две половины пары
с линией между ними, перевёрнутые цифры дат.

Новый снапшот с сайта (2026-10-09, 6748 занятий из парсера, 6572 после очистки) против
старого: без дисциплины 157 → 7, без преподавателя 227 → 59, без аудитории 282 → 177,
склеенных ячеек 403 → 131, подозрительных групп 35 → 0, на проверку 509 → 222. Новые
написания (38 дисциплин, 5 преподавателей, 11 групп) проверены вручную и внесены в словарь.
Даты заочки прочитаны во всех датированных файлах; без дат один файл («Б-ЗК-51,52,53 от
14.09.2026»), в его таблице дат нет.
