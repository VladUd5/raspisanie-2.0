# Расписание 2.0 → прод: две версии сайта, изменения, календарь, сообщения об ошибках

Дата: 2026-10-13. Статус: согласовано в обсуждении; письменную спеку пользователь разрешил
не ждать на ревью (автономная работа), правки — после.

## Цель

Стенд сейчас понятен программисту и аналитику. Нужен продукт для двух аудиторий:

- **студенты и преподаватели** — быстро найти своё расписание с телефона, узнать об изменениях;
- **руководство** — нагрузка, аудитории, изменения, сообщения пользователей.

Хостинг — Docker на сервере вуза, ~20 посетителей в час, пики при выкладке расписания
(до 100–200 одновременно). Версии различаются адресом, **без логинов и паролей**.

## Решения, принятые в обсуждении

| Вопрос | Решение |
|---|---|
| Обратная связь | В обе стороны: сайт сообщает об изменениях; пользователь сообщает об ошибке |
| Каналы уведомлений | Страница «Изменения» + пометки на занятиях; подписка на календарь (.ics). Telegram — позже. Email — нет |
| Сообщения об ошибках | Раздел «Сообщения» в версии руководства, статусы. Форма анонимная, **без поля контакта** (версия руководства открыта — персональные данные не храним) |
| Стек | Студенты — FastAPI + HTML-шаблоны; руководство — Streamlit (текущий стенд без демо-частей) |
| Защита версии руководства | Нет (отдельный адрес). Поэтому даты семестра — в `.env`, а не на сайте; кнопка «Проверить сайт сейчас» безвредна (блокировка + пауза) |
| Недели | Семестр всегда начинается с верхней недели, дальше чередуются. Осень — 1 сентября – 31 декабря; весна задаётся в `.env` |
| Расписание очников, очно-заочников | Стоит весь семестр, правки редки |
| Заочники | Новая неделя сессии каждую неделю; **все недели храним** (архив) |
| Нагрузка заочников | Занятие засчитывается по версии, актуальной на его дату; переделки недели не суммируются |
| Часовой пояс | `Europe/Saratov` (UTC+4) |
| Адреса | Студенты — `/`, руководство — `/rukovodstvo` |
| Сбор | Ежедневно 03:00 и 13:00 по Саратову |
| Демо-части | «Обзор и пайплайн» и кнопка сбора удаляются; «Качество данных», «Словарь написаний», «История сборов» — в свёрнутом разделе «Служебное» у руководства |

## 1. Архитектура

```
cron в collector (03:00, 13:00) ─→ parser ─→ снапшот JSON ─→ очистка ─→ schedule.db ─→ публикация + изменения
                                                                   │
         public (FastAPI :8000) ← читает ──────────────────────────┤
         staff (Streamlit :8501, /rukovodstvo) ← читает ───────────┘
         public пишет сообщения → feedback.db ← staff читает и меняет статус
         nginx (:80): / → public, /rukovodstvo → staff
```

Контейнеры (один образ стенда, разные команды): `parser` (без изменений), `collector`,
`public`, `staff`, `proxy` (nginx). Писатель `schedule.db` в проде один — `collector`;
`public` только читает. `staff` сохраняет прежнее поведение «подхватить новые файлы» для запуска
без Docker.

Хранилище:

- `data/snapshots/*.json` — источник истины, хранятся бессрочно. Сбор, совпавший с последним
  сохранённым (те же данные корпусов), **не сохраняется**: только время проверки.
- `data/schedule.db` — пересобираемый кэш (как сейчас) + статус публикации снапшотов и таблица
  изменений. Режим WAL, чтобы чтение не ждало записи.
- `data/feedback.db` — сообщения пользователей. Схема не удаляется, только пошаговые миграции.
- `data/status.json` — последний сбор: время, результат, сообщение (пишет collector).
- `data/collect.request` — запрос «проверить сайт сейчас» (создаёт staff, забирает collector).

## 2. Публикация и изменения

**Публикация.** Снапшоты обрабатываются по времени сбора. Снапшот, в котором занятий меньше
`PUBLISH_MIN_RATIO` (0.7) от последнего опубликованного, **не публикуется** (сайт вуза лёг, PDF
не скачались) — пометка «сбор выглядит неполным» видна руководству. Первый снапшот публикуется
всегда.

**Актуальное расписание** (его видят обе версии):

- недатированные занятия (очники, очно-заочники, заочники без дат) — из последнего опубликованного
  снапшота;
- датированные (заочники) — архив недель: для пары (группа, неделя сессии) берутся все
  опубликованные снапшоты, где эта неделя есть; для каждой даты недели — последний из них,
  собранный не позже этой даты (по Саратову), а если такого нет — самый ранний. Будущие даты так
  получают самую свежую версию, прошедшие — ту, что была на день занятия; переделки не
  суммируются. Неделя, которой нет в последнем снапшоте, остаётся из архива.

**Ключ занятия** при сравнении: институт, форма, группа, дата (у заочников) / день недели, время
начала, верхняя/нижняя неделя, подгруппа. Содержимое слота — множество занятий (тип, дисциплина,
преподаватели, аудитории) после очистки и склейки написаний.

**Виды изменений** (каждый опубликованный снапшот против предыдущего опубликованного):

| Вид | Когда |
|---|---|
| `added` / `removed` | слот появился / пропал |
| `changed` | слот есть в обоих, содержимое разное; текст «было → стало» |
| `moved` | у группы пропало занятие и появилось такое же (тип, дисциплина, преподаватели) в другом слоте той же формы; одно событие вместо двух |
| `week_published` | у группы появилась неделя сессии, которой раньше не было (заочники) |
| `week_removed` | будущая неделя сессии пропала с сайта; у нас она остаётся в архиве |
| `major_update` | в форме обучения изменилось больше `MAJOR_CHANGE_RATIO` (0.3) слотов (новый семестр): одна строка на форму вместо поштучных |

Датированные слоты сравниваются только внутри недель, которые есть в обоих снапшотах, и только
для дат не раньше дня сбора нового снапшота (прошедшие даты — история, её не трогаем).

Изменения хранятся в `schedule.db` (`changes`) и пересчитываются из снапшотов при пересборке.
Пометка «изменено» на занятии у студентов видна `CHANGE_BADGE_DAYS` (7) дней.

## 3. Студенческая версия (public)

Адреса: `/` (поиск), `/g/<группа>`, `/t/<преподаватель>`, `/r/<корпус>/<аудитория>`,
`/changes`, `/g/<группа>.ics`, `/t/<преподаватель>.ics`, `POST /report`, `/healthz`.
Необязательный `?week=YYYY-MM-DD` — понедельник показываемой недели.

- **Главная**: строка поиска с подсказками (группы, преподаватели, аудитории; без учёта регистра,
  с допуском опечаток), без JS — обычная форма с результатами. «Недавно открытые» — в браузере.
- **Неделя**: карточки по дням, сегодня подсвечено, «идёт сейчас» — у текущего занятия. Очники:
  неделя (верхняя/нижняя) вычисляется по дате начала семестра, видны только её занятия; вне
  семестра — обе недели с пометками. Заочники: по умолчанию текущая или ближайшая неделя сессии,
  стрелки листают недели архива.
- Преподаватель и аудитория — ссылки; поток для нескольких групп — одно занятие со списком групп.
- Пометка «изменено» с «было → стало», «отменено» (7 дней).
- У занятия «Ошибка в расписании?» — `<details>` с формой, контекст подставлен.
- Подвал: «Проверено на сайте вуза: …», ссылка на изменения.
- Мобильная вёрстка первым делом, светлая/тёмная тема по системе, свой CSS, без внешних CDN.
- Данные держатся в памяти процесса и перечитываются при изменении `schedule.db` (mtime);
  ответы сжаты (gzip).

## 4. Календарь и сообщения

**.ics**: группа (необязательно `?sub=N` — общие занятия + подгруппа N) или преподаватель.

- Очники: занятия с 14 дней назад до конца текущего семестра, верхняя/нижняя неделя
  разворачиваются в даты. Вне семестра — пустой календарь с пояснением в описании.
- Заочники: все датированные занятия архива начиная с 14 дней назад.
- `UID` постоянный: хэш (группа/преподаватель, дата, время, подгруппа, дисциплина). Изменённое
  занятие обновляется на месте, в описании «Изменено …: было → стало». Отменённое — 7 дней со
  `STATUS:CANCELLED`.
- `TZID=Europe/Saratov` с `VTIMEZONE`; `REFRESH-INTERVAL`/`X-PUBLISHED-TTL` = 6 часов (подсказка;
  Google сам решает, когда перечитывать — об этом сказано в инструкции на сайте).

**Сообщения**: поля «что не так» (список), комментарий (до 1000 символов); контекст (страница,
группа/преподаватель/аудитория, занятие, снапшот) подставляется. Ловушка для ботов, не больше
`REPORTS_PER_HOUR` (5) с адреса; адрес хранится только солёным хэшем, строки старше суток
удаляются. Статусы: новое → в работе → исправлено / отклонено; каждое действие пишется в журнал.

## 5. Версия для руководства (staff)

Источник данных — актуальное расписание (выбора снапшота нет). Меню:

- **Сводка** (по умолчанию): статус данных (последняя проверка, предупреждения: неполный сбор,
  снятая неделя, нет дат семестра), изменения за 7 дней, новые сообщения, ключевые цифры.
- Преподаватели, Аудитории, Дисциплины, Группы, Инфографика — как сейчас.
- **Изменения**: за период, фильтры (институт, форма, группа, вид), выгрузка в Excel.
- **Сообщения (N)**: список, смена статуса, заметка, журнал.
- Выгрузка.
- *Служебное*: История сборов (статус collector'а, снапшоты и их публикация, даты семестра из
  `.env`, «Проверить сайт сейчас»), Качество данных, Словарь написаний.

Фильтры на виду: институт, форма, корпус, группа, неделя сессии. Тип занятия, день, неделя
верх./нижн., «полной парой», единица часов — в свёрнутом «Дополнительно». Правила подсчёта
нагрузки не меняются.

## 6. Развёртывание

`docker compose up -d --build` поднимает всё; снаружи один порт (`HTTP_PORT`, по умолчанию 80):
`/` и `/rukovodstvo`. Пример конфигурации для nginx вуза — в `deploy/`. Рекомендуемый сервер:
2 vCPU, 4 ГБ RAM, 20 ГБ диска (минимум 1 vCPU / 2 ГБ). Для календаря нужен публичный HTTPS-адрес.

Настройки (`.env`): `TZ_NAME`, `COLLECT_TIMES`, `AUTUMN_START`, `AUTUMN_END`, `SPRING_START`,
`SPRING_END`, `PUBLISH_MIN_RATIO`, `MAJOR_CHANGE_RATIO`, `CHANGE_BADGE_DAYS`, `REPORTS_PER_HOUR`,
`SITE_TITLE`, `PUBLIC_URL`, `STAFF_BASE_PATH`.

## 7. Проверка

pytest: календарь недель, публикация и архив недель, сравнение снапшотов (каждый вид изменения),
.ics, хранилище сообщений и ограничение частоты, маршруты public (TestClient), страницы staff
(AppTest). Ручная проверка — `docker compose up` и обход страниц.

## Вне рамок

Telegram-бот; поиск свободной аудитории у студентов; печатная версия; подсчёт нагрузки заочников
по месяцу/семестру отдельным переключателем (есть «все недели вместе»); уточнение у вуза текста
согласия на ПДн (контакт не собираем).
