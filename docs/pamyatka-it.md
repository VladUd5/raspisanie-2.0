# Расписание 2.0 — памятка для отдела ИТ

Сайт расписания занятий. Данные собираются автоматически с www.vavilovsar.ru, ручной ввод не нужен.

- `/` — сайт для студентов и преподавателей;
- `/rukovodstvo/` — версия для руководства. Открыта без пароля по решению заказчика; при
  необходимости закрывается паролем или списком адресов (см. «Закрыть версию для руководства»).

Памятка написана так, чтобы установку можно было пройти по шагам, не зная Docker заранее. Все
команды выполняются в терминале сервера; строки, начинающиеся с `#`, — пояснения, их вводить не
нужно. Вместо `<…>` подставляются свои значения.

## Словарь

| Термин | Что это |
|---|---|
| Сервер | компьютер или виртуальная машина с Linux, на которой работает сайт |
| Терминал, SSH | окно для ввода команд; к серверу подключаются по SSH: `ssh <пользователь>@<адрес сервера>` |
| `sudo` | выполнить команду с правами администратора; спросит пароль пользователя |
| IP-адрес | числовой адрес сервера в сети, например `10.0.12.34` |
| Порт | номер «входа» на сервере: 80 — обычный сайт (HTTP), 443 — защищённый (HTTPS), 22 — SSH |
| Домен, DNS | имя сайта (`raspisanie.vavilovsar.ru`) и служба, которая превращает имя в IP-адрес. **A-запись** — строка в DNS «имя → IP» |
| HTTP, HTTPS | протоколы сайта; HTTPS — шифрованный, адрес начинается с `https://`, в браузере замок |
| Сертификат (TLS/SSL) | файл, подтверждающий, что сайт настоящий; без него HTTPS не работает. Выдаётся на конкретное имя сайта и имеет срок действия |
| Let's Encrypt, certbot | бесплатный центр сертификатов и программа, которая получает и сама продлевает сертификат |
| Прокси (обратный прокси) | сервер, который принимает запросы из интернета и пересылает их на внутренний сервер. Обычно на нём же включают HTTPS |
| nginx | популярная программа для прокси и веб-серверов; в проекте — контейнер `proxy` |
| Docker | программа, которая запускает приложения в изолированных «коробках» — контейнерах. Не нужно ставить Python, библиотеки и прочее на сам сервер |
| Образ | заготовка контейнера: программа со всем нужным. Собирается командой `docker compose build` или скачивается (Docker Hub) |
| Контейнер | запущенный образ. У проекта их пять: `parser`, `collector`, `public`, `staff`, `proxy` |
| Docker Compose | описание всех контейнеров проекта в одном файле (`docker-compose.yml`) и команда `docker compose`, которая ими управляет |
| Проверка здоровья (healthcheck) | контейнер раз в 30 секунд проверяет сам себя; в `docker compose ps` видно `(healthy)` или `(unhealthy)` |
| git, репозиторий | система хранения кода и сам код проекта на GitHub. `git clone` — скачать, `git pull` — обновить |
| Подмодуль (submodule) | отдельный репозиторий внутри проекта (парсер PDF, папка `vendor/`); скачивается с ключом `--recurse-submodules` |
| `.env` | текстовый файл с настройками проекта рядом с `docker-compose.yml`. Образец — `.env.example` |
| `data/` | папка с данными: база, архив версий расписания, резервные копии. Её нужно беречь |
| Снапшот | одна сохранённая версия расписания с сайта вуза (`data/snapshots/*.json`) |
| WebSocket | постоянное соединение браузера с сервером; без него не работает версия для руководства |
| `X-Forwarded-For` | заголовок, в котором прокси передаёт настоящий адрес посетителя |
| Межсетевой экран (firewall) | правила, какие порты сервера открыты и для кого |
| cron | встроенный в Linux планировщик задач, например для копирования резервных копий |
| `.ics`, подписка | файл расписания для календарей (Google, Apple и других) и ссылка на него, по которой календарь сам обновляется |

## Как устроено

```
 Студент / руководство (браузер, календарь телефона)
            │  https://raspisanie.vavilovsar.ru   (порт 443)
            ▼
 Прокси вуза: HTTPS, сертификат
            │  http://<сервер>:80
            ▼
 Сервер расписания (Docker)
   proxy (nginx) ──/──────────────► public   — сайт для студентов
                 └─/rukovodstvo/──► staff    — версия для руководства
   collector ──► parser ──► https://www.vavilovsar.ru (PDF-расписания, графики)
       │
       └──► data/  (база, снапшоты, резервные копии)
```

**Сайт** должен открываться из интернета по адресу `https://raspisanie.vavilovsar.ru` — иначе не
работает подписка на календарь (Google забирает расписание со своих серверов). Но **сам сервер
расписания** может стоять во внутренней сети без публичного IP-адреса: из интернета видят только
прокси вуза, а прокси пересылает запросы на сервер. Серверу достаточно, чтобы до него доходил
прокси, а сам он мог ходить на www.vavilovsar.ru.

## Требования

| | |
|---|---|
| Сервер | Linux x86-64 (проверено на Ubuntu), 2 vCPU, 4 ГБ RAM, 20 ГБ SSD (минимум 1 vCPU, 2 ГБ, 10 ГБ; на 1 vCPU сбор расписания и сборка идут дольше, а сайт во время сбора отвечает медленнее) |
| ПО | Docker Engine, Docker Compose v2.24+, git |
| Нагрузка | в обычном режиме — доли процента CPU, около 0,8 ГБ RAM |
| Входящие | один HTTP-порт (`HTTP_PORT`, по умолчанию 80) — только от прокси вуза |
| Исходящие при работе | `www.vavilovsar.ru:443` — расписание (пн, чт 03:00), графики (ежедневно), справочник кафедр (раз в 30 дней) |
| Исходящие при установке | `github.com`, Docker Hub (`python:3.10-slim`, `golang:1.25-bookworm`, `nginx:1.27-alpine`), `pypi.org`, `files.pythonhosted.org`, `proxy.golang.org` |
| Имя сайта | отдельный поддомен, например `raspisanie.vavilovsar.ru` (см. «Публикация») |

## Установка по шагам

### 1. Подключиться к серверу

```bash
ssh <пользователь>@<адрес сервера>
```

### 2. Установить Docker и git

```bash
sudo apt update
sudo apt install -y git curl
# официальный установщик Docker (Ubuntu, Debian)
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo systemctl enable --now docker       # Docker стартует вместе с сервером
# чтобы не писать sudo перед каждой командой docker:
sudo usermod -aG docker $USER
exit                                     # выйти и подключиться по SSH заново
```

Проверка после повторного входа:

```bash
docker --version
docker compose version                   # должно быть v2.24 или новее
docker run --rm hello-world              # «Hello from Docker!» — всё в порядке
```

Если выход в интернет идёт через HTTP-прокси, его нужно указать для службы Docker
(`/etc/systemd/system/docker.service.d/http-proxy.conf`) и для сборки (`~/.docker/config.json`,
раздел `proxies`). Если Docker Hub недоступен, в `/etc/docker/daemon.json` указывается зеркало
(`"registry-mirrors": ["https://<зеркало>"]`) и выполняется `sudo systemctl restart docker`.

### 3. Скачать проект

```bash
cd ~
git clone --recurse-submodules https://github.com/VladUd5/raspisanie-2.0.git raspisanie
cd raspisanie
```

Все дальнейшие команды `docker compose …` выполняются из этой папки (`~/raspisanie`).

### 4. Настройки

```bash
cp .env.example .env
nano .env
```

В редакторе `nano`: стрелками к нужной строке, исправить, затем `Ctrl+O`, `Enter` — сохранить,
`Ctrl+X` — выйти. На этом шаге достаточно двух строк:

```
PUBLIC_URL=https://raspisanie.vavilovsar.ru   # адрес, по которому сайт будут открывать
HTTP_PORT=80                                  # если порт 80 занят — другой, например 8080
```

Остальные параметры имеют рабочие значения по умолчанию. Без `PUBLIC_URL` сайт тоже работает, не
работает только подписка на календарь — его можно вписать позже, когда будет готово имя сайта.

### 5. Запуск

```bash
docker compose up -d --build      # первая сборка — около 12 минут
docker compose ps                 # public, staff, collector, proxy — (healthy); parser — Up
```

`-d` — работать в фоне; `--build` — собрать образы. Сразу после запуска статус может быть
`(health: starting)` — через минуту-две он станет `(healthy)`.

### 6. Проверка на самом сервере

```bash
curl http://localhost/healthz     # {"ok":true}   (при HTTP_PORT=8080 — http://localhost:8080/healthz)
```

С другого компьютера в сети вуза открыть в браузере `http://<IP сервера>/` — сайт для
студентов, и `http://<IP сервера>/rukovodstvo/` — версия для руководства. В репозитории есть
снапшот расписания, поэтому данные видны сразу; свежее расписание подтянется при ближайшем сборе
или по кнопке «Проверить сайт сейчас» на «Сводке» версии для руководства.

## Публикация

### Имя сайта

Сайт нужно разместить **на отдельном поддомене**, например `raspisanie.vavilovsar.ru`. Положить
его в папку основного сайта (`vavilovsar.ru/raspisanie/`) нельзя: ссылки внутри сайта начинаются
с корня (`/static/…`, `/g/…`) и в папке ломаются.

1. Администратор DNS домена `vavilovsar.ru` добавляет A-запись:
   `raspisanie.vavilovsar.ru → <IP прокси вуза>` (или IP самого сервера, если прокси нет).
2. Проверка (через несколько минут, иногда до часа): `getent hosts raspisanie.vavilovsar.ru` — в
   ответе нужный IP.
3. На основном сайте вуза ставится обычная ссылка на `https://raspisanie.vavilovsar.ru` —
   в меню «Студентам», «Расписание» и т. п.

### Вариант А. Через прокси вуза (рекомендуется)

Сайт отдаёт HTTP; HTTPS — на прокси вуза, который пересылает запросы на
`http://<сервер>:<HTTP_PORT>`. Требования к прокси:

- для `/rukovodstvo/` — поддержка WebSocket (`Upgrade`, `Connection`) и увеличенный
  `proxy_read_timeout`;
- передача адреса клиента в `X-Forwarded-For`.

Пример для прокси вуза на nginx (файл, например, `/etc/nginx/conf.d/raspisanie.conf`):

```nginx
map $http_upgrade $connection_upgrade { default upgrade; '' close; }

server {                                   # http → https
    listen 80;
    server_name raspisanie.vavilovsar.ru;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name raspisanie.vavilovsar.ru;
    ssl_certificate     /etc/ssl/<путь>/fullchain.pem;   # сертификат вместе с промежуточными
    ssl_certificate_key /etc/ssl/<путь>/privkey.pem;

    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto https;

    location / {
        proxy_pass http://<IP сервера расписания>:80;
    }
    location /rukovodstvo/ {
        proxy_pass http://<IP сервера расписания>:80;
        proxy_http_version 1.1;
        proxy_read_timeout 86400;
        # в блоке есть свои proxy_set_header — общие сверху не наследуются, поэтому все заново
        proxy_set_header Upgrade $http_upgrade;          # WebSocket
        proxy_set_header Connection $connection_upgrade;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

Проверка и применение на прокси: `sudo nginx -t` (должно быть `syntax is ok`), затем
`sudo systemctl reload nginx`. Если у вуза есть сертификат на `*.vavilovsar.ru`, подойдёт он.

Затем на сервере расписания — чтобы ограничение частоты запросов считалось для каждого
посетителя, а не одно на всех (все запросы приходят с адреса прокси): в `deploy/nginx.conf`
внутри блока `server { … }` добавить

```nginx
set_real_ip_from <IP прокси вуза>;
real_ip_header X-Forwarded-For;
```

и выполнить `docker compose restart proxy`. При следующем `git pull` git сообщит, что файл
изменён локально: `git stash && git pull --recurse-submodules && git stash pop` — правка сохранится.

### Вариант Б. Сервер сам смотрит в интернет

Если прокси вуза нет, HTTPS включается на самом сервере расписания: системный nginx с
сертификатом Let's Encrypt принимает 80/443 и пересылает на контейнер, который слушает только
внутренний адрес.

1. В `.env`: `HTTP_PORT=127.0.0.1:8080` — контейнер доступен только с самого сервера; затем
   `docker compose up -d`.
2. Установить nginx и certbot:

   ```bash
   sudo apt install -y nginx certbot python3-certbot-nginx
   ```

3. Создать `/etc/nginx/conf.d/raspisanie.conf` (`sudo nano /etc/nginx/conf.d/raspisanie.conf`):

   ```nginx
   map $http_upgrade $connection_upgrade { default upgrade; '' close; }

   server {
       listen 80;
       server_name raspisanie.vavilovsar.ru;

       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

       location / {
           proxy_pass http://127.0.0.1:8080;
       }
       location /rukovodstvo/ {
           proxy_pass http://127.0.0.1:8080;
           proxy_http_version 1.1;
           proxy_read_timeout 86400;
           proxy_set_header Upgrade $http_upgrade;
           proxy_set_header Connection $connection_upgrade;
           proxy_set_header Host $host;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       }
   }
   ```

   Применить: `sudo nginx -t && sudo systemctl reload nginx`. Если nginx не стартует из-за
   занятого порта 80 — значит, `HTTP_PORT` в `.env` всё ещё `80` (шаг 1).
4. Получить сертификат (DNS уже должен указывать на сервер, порт 80 открыт из интернета):

   ```bash
   sudo certbot --nginx -d raspisanie.vavilovsar.ru
   ```

   certbot сам допишет HTTPS в настройку nginx и будет продлевать сертификат. Проверка
   продления: `sudo certbot renew --dry-run`.
5. В `deploy/nginx.conf` добавить `set_real_ip_from 172.16.0.0/12;` и
   `real_ip_header X-Forwarded-For;` (запросы приходят из сети Docker), затем
   `docker compose restart proxy`.

### Закрыть версию для руководства

По умолчанию `/rukovodstvo/` открыта всем, кто видит сайт. Закрыть можно на прокси вуза, в блоке
`location /rukovodstvo/`:

```nginx
# только из сети вуза
allow 10.0.0.0/8;          # подставить свои сети
deny  all;
```

или паролем:

```bash
sudo apt install -y apache2-utils
sudo htpasswd -c /etc/nginx/.htpasswd rukovodstvo     # спросит пароль
```

```nginx
auth_basic "Расписание — руководство";
auth_basic_user_file /etc/nginx/.htpasswd;
```

После правки — `sudo nginx -t && sudo systemctl reload nginx`. Подписку на календарь это не
затрагивает: она работает через `/`.

### Межсетевой экран

Порт сервера расписания (`HTTP_PORT`) должен быть доступен только прокси вуза. Важно: порты,
открытые Docker, **не подчиняются правилам `ufw`** — `ufw deny 80` их не закроет. Ограничивать
доступ нужно на межсетевом экране сети вуза или привязкой порта к адресу (`HTTP_PORT=<IP>:80`,
как в варианте Б).

## Подписка на календарь

На странице группы или преподавателя есть кнопки «iPhone, iPad, Mac» и «Google Календарь». Они
добавляют в календарь пользователя не копию расписания, а **ссылку** на файл вида
`https://<имя сайта>/g/<группа>.ics`. Календарь сам заходит по этой ссылке раз в несколько часов и
забирает свежее расписание, поэтому замены и переносы появляются у студента без его участия.

Отсюда три условия. Пока они не выполнены, сайт работает, а подписка — нет.

| Условие | Зачем |
|---|---|
| Сайт открыт **из интернета**, а не только из сети вуза | Google Календарь скачивает расписание со своих серверов, а не с телефона студента. iPhone тоже обновляет подписку вне университетского Wi-Fi |
| Адрес начинается с **`https://`**, сертификат действительный | без HTTPS календарные сервисы работают ненадёжно, браузеры помечают сайт как «небезопасный» |
| Этот адрес записан в **`PUBLIC_URL`** в `.env` | из него сайт строит ссылки подписки; без него в ссылки попадает адрес, по которому сайт открыли, часто внутренний |

После правки `PUBLIC_URL` выполнить `docker compose up -d`. Команда пересоздаёт только контейнеры,
у которых изменились настройки; данные не затрагиваются. `docker compose restart` новые настройки
из `.env` **не** подхватывает.

### Как проверить

1. С компьютера **вне сети вуза** (или с телефона по мобильному интернету) открыть
   `https://<имя сайта>/` — сайт открывается, замок в адресной строке без предупреждений.
2. Открыть страницу любой группы, внизу «Расписание в календаре телефона» → «Как подписаться
   вручную». Ссылка должна начинаться с `https://<имя сайта>/g/…`, а не с `localhost`, IP-адреса
   или внутреннего имени.
3. Проверить сам файл:

   ```bash
   curl -sI "https://<имя сайта>/g/Б-А-301.ics" | grep -i content-type   # text/calendar
   ```

4. Подписаться с телефона кнопкой «iPhone, iPad, Mac» и через «Google Календарь» на компьютере.
   Занятия появляются в течение минуты (в Google — до нескольких минут); время, аудитории и
   преподаватели совпадают с сайтом.

### Если не работает

| Признак | Причина и что сделать |
|---|---|
| В ссылках подписки `localhost`, IP-адрес или внутреннее имя | не задан `PUBLIC_URL` или после правки не выполнен `docker compose up -d` |
| Ссылки начинаются с `http://` | в `PUBLIC_URL` записан `http://` — исправить на `https://` |
| Google: «Не удалось добавить календарь» | сайт не открывается из интернета или сертификат недействителен (просрочен, выдан на другое имя, не хватает промежуточного) |
| iPhone подписался, но после выхода из сети вуза расписание не обновляется | сайт доступен только изнутри |
| Подписка есть, но замена появилась только через сутки | так работает Google: он обновляет подписки раз в 8–24 часа и ускорить это нельзя. iPhone обновляет чаще, на Mac — «Вид» → «Обновить календари» |
| Файл `.ics` отдаёт 503 «Данные готовятся» | сайт только что запущен и ещё загружает расписание — подождать минуту |

Если адрес сайта когда-нибудь сменится, старые подписки перестанут обновляться и студентам
придётся подписаться заново. Поэтому имя сайта лучше выбрать один раз и не менять.

## Сопровождение

| | |
|---|---|
| Мониторинг | `GET /healthz` → `{"ok":true}`; рекомендуется подключить к Zabbix |
| Автовосстановление | перезапуск упавших и зависших контейнеров, старт вместе с Docker, лимиты памяти, ротация логов |
| Резервные копии | ежедневно в `data/backups/` (14 последних); нужно копировать на другой сервер (см. ниже) |

Как устроены сбор данных и резервные копии, откат обновления и неполадки со сбором расписания — в
README.

### Шпаргалка команд

Все команды — из папки проекта (`cd ~/raspisanie`).

| Задача | Команда |
|---|---|
| Состояние контейнеров | `docker compose ps` |
| Журнал за последний час | `docker compose logs --since 1h public` (или `staff`, `collector`, `parser`, `proxy`) |
| Журнал в реальном времени | `docker compose logs -f collector` (выход — `Ctrl+C`) |
| Перезапустить один контейнер | `docker compose restart public` |
| Остановить всё | `docker compose down` (данные в `data/` сохраняются) |
| Запустить всё | `docker compose up -d` |
| Применить правку `.env` | `docker compose up -d` |
| Обновить до новой версии | `git pull --recurse-submodules && docker compose up -d --build` |
| Собрать расписание сейчас | `docker compose exec collector python collector.py once` |
| Резервная копия сейчас | `docker compose exec collector python collector.py backup` |
| Список резервных копий | `ls -lh data/backups/` |
| Место на диске | `df -h` и `docker system df` |
| Удалить старые образы после обновлений | `docker image prune -f` |
| Проверить, что сайт отвечает | `curl http://localhost/healthz` |

### Копирование резервных копий на другой сервер

Копии лежат на том же диске, что и сайт, — при поломке диска пропадут вместе с ним. Пример
ежедневного копирования в 06:00 на сервер `<сервер копий>` (нужен вход по SSH-ключу без пароля):

```bash
ssh-keygen -t ed25519                         # один раз, на все вопросы — Enter
ssh-copy-id <пользователь>@<сервер копий>     # один раз
crontab -e                                    # добавить строку:
0 6 * * * rsync -a ~/raspisanie/data/backups/ <пользователь>@<сервер копий>:/backups/raspisanie/
```

Восстановление из копии — в README, раздел «Резервные копии».

### Частые проблемы

| Признак | Что сделать |
|---|---|
| `permission denied … docker.sock` | пользователь не в группе `docker`: `sudo usermod -aG docker $USER` и войти по SSH заново |
| `port is already allocated` / `address already in use` при запуске | порт занят (часто системным nginx или Apache): `sudo ss -ltnp \| grep :80` — кто занял; либо задать другой `HTTP_PORT` в `.env` |
| Сборка падает на скачивании (`timeout`, `TLS handshake`, `pull access denied`) | нет доступа к Docker Hub, PyPI или GitHub — настроить прокси или зеркало (шаг 2) |
| Контейнер `(unhealthy)` или постоянно перезапускается | `docker compose logs --since 1h <контейнер>` — в конце журнала причина |
| В браузере «Сайт перезапускается» | `public` или `staff` перезапускается; обычно проходит за минуту. Если дольше — смотреть журнал |
| `429 Слишком много запросов` у всех сразу | за прокси вуза не настроен `set_real_ip_from` (вариант А) |
| Версия для руководства открывается, но «крутится» и не грузится | на прокси не включён WebSocket для `/rukovodstvo/` |
| На сайте старое расписание | «Сводка» в версии для руководства: время последней проверки и предупреждения; журнал `collector` |
| Закончилось место на диске | `docker image prune -f`, `docker system df`; старые резервные копии удаляются сами |
