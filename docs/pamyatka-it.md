# Расписание 2.0 — памятка для отдела ИТ

Сайт с расписанием занятий вуза. Данные он сам дважды в неделю (пн и чт) берёт с www.vavilovsar.ru
(PDF расписаний), людям ничего вводить не нужно; внеочередной сбор — кнопкой в версии для руководства. Два адреса на одном порту:

- `/` — сайт для студентов и преподавателей;
- `/rukovodstvo/` — версия для руководства (аналитика, сообщения об ошибках, даты сессий).
  Открыта без пароля по решению заказчика; если нужно закрыть — Basic Auth или список адресов на
  прокси вуза для пути `/rukovodstvo/`.

## Что нужно от сервера

| | |
|---|---|
| Машина | Linux x86-64, 2 vCPU, 4 ГБ RAM, 20 ГБ SSD (минимум 2 vCPU, 2 ГБ, 10 ГБ) |
| ПО | Docker Engine и Docker Compose v2.24+, git |
| Нагрузка | ~20 посетителей в час — доли процента процессора; постоянно занято ~0,8 ГБ памяти |
| Входящие | один HTTP-порт (`HTTP_PORT`, по умолчанию 80) — для прокси вуза |
| Исходящие при работе | `www.vavilovsar.ru` (HTTPS) — сбор расписания в пн и чт в 03:00, графики учебного процесса и справочник кафедр раз в сутки |
| Исходящие при установке и обновлении | `github.com`, Docker Hub (`registry-1.docker.io`, образы `python:3.10-slim`, `golang:1.25-bookworm`, `nginx:1.27-alpine`), PyPI (`pypi.org`, `files.pythonhosted.org`), модули Go (`proxy.golang.org`) |

Если выход в интернет только через HTTP-прокси — его нужно прописать для службы Docker
(`/etc/systemd/system/docker.service.d/http-proxy.conf`) и для сборки (`~/.docker/config.json`,
раздел `proxies`).

## HTTPS и имя

Сайт отдаёт HTTP; сертификат и HTTPS — на прокси вуза, который пересылает запросы на
`http://<сервер>:<HTTP_PORT>`. Для `/rukovodstvo/` прокси должен пропускать WebSocket
(`Upgrade`, `Connection`) и не обрывать соединение через минуту (`proxy_read_timeout` побольше).
Образец настройки nginx — `deploy/nginx.conf`.

Наш nginx ограничивает частоту запросов с одного адреса. За прокси вуза все приходят с адреса
прокси, поэтому в `deploy/nginx.conf` нужно добавить `set_real_ip_from <адрес прокси>;` и
`real_ip_header X-Forwarded-For;`.

## Установка

```bash
sudo systemctl enable --now docker
git clone --recurse-submodules https://github.com/VladUd5/raspisanie-2.0.git "Расписание 2.0"
cd "Расписание 2.0"
cp .env.example .env
nano .env        # PUBLIC_URL=https://<имя сайта>, при необходимости HTTP_PORT
docker compose up -d --build      # первый раз ~12 минут
docker compose ps                 # public, staff, collector, proxy — (healthy)
```

Расписание видно сразу: в репозитории лежит последний снапшот, свежий collector соберёт по расписанию.

## Что настроить в `.env`

- `PUBLIC_URL` — внешний адрес сайта с `https://` (ссылки подписки на календарь).
- `HTTP_PORT` — порт, на который смотрит прокси вуза.
- Даты семестров и праздники задавать не нужно — они берутся из графиков учебного процесса и
  производственного календаря. При необходимости их можно задать в `.env` (описано там же).

Остальное — значения по умолчанию, описаны в самом `.env.example`.

## Сам поднимается после сбоев

- упавший контейнер Docker перезапускает за секунды; зависший перезапускает себя сам (~1,5 мин);
- после перезагрузки сервера всё поднимается вместе со службой Docker;
- у каждого контейнера предел памяти и ротация логов (3 × 10 МБ).

Мониторинг: `GET /healthz` отвечает `{"ok":true}`. Стоит поставить его в Zabbix или аналог —
зависание всей машины или переполненный диск изнутри не лечатся.
