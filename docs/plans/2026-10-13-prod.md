# Прод: студенты + руководство — план реализации

> Исполнение: inline в одной сессии (пользователь попросил автономную работу), по задачам,
> тесты на каждую, коммит после каждой.

**Цель:** из стенда — продукт: студенческий сайт (FastAPI), версия для руководства (Streamlit),
автосбор, изменения, календарь, сообщения об ошибках.

**Спека:** `docs/specs/2026-10-13-prod-design.md`.

**Стек:** Python 3.10, SQLite, pandas, Streamlit 1.65, FastAPI + Jinja2 + uvicorn, nginx.

## Глобальные ограничения

- Часовой пояс `Europe/Saratov`; «сегодня» и даты сбора — по нему.
- Верхняя неделя = `numerator`, нижняя = `denominator`; неделя начала семестра — верхняя.
- `schedule.db` — пересобираемый кэш (`SCHEMA_VERSION` → 4); `feedback.db` — никогда не удаляется.
- Никаких внешних CDN в public; без JS страницы работают.
- Тексты для пользователя — по-русски, без слов «снапшот», «выборка», «канон» у студентов.
- В коммитах нет упоминаний ИИ.

## Review Focus

1. Группа с одинаковым именем в разных институтах/формах — страница показывает обе, не падает.
2. Имена с `/`, пробелами, точками и кириллицей в адресах (`/t/Аленичева Н.В.`, `/r/УК1/С-12`) открываются.
3. Пустая база (сбора ещё не было) — public отдаёт «данные готовятся», а не 500; staff — подсказку.
4. Неделя вне семестра (каникулы, весна не задана) — очники видят обе недели с пометками, .ics пустой, без исключений.
5. Повторная отправка формы и ботовое поле — 429/тихое игнорирование, не дубли в базе.

## Задачи

### 1. Настройки и календарь семестра
- `semester.py`: `today() -> date`, `now() -> datetime` (TZ из настроек); `semester_for(d) -> tuple[date, date] | None`;
  `week_type_on(d) -> 'numerator'|'denominator'|None`; `monday(d) -> date`.
- Тесты: 1 сентября (вторник) — неделя верхняя; 8 сентября — нижняя; 31 декабря — в семестре;
  15 января без весны — `None`; весна из env — верхняя в неделю старта.

### 2. Схема v4, сравнение и публикация
- `diff.compare(old: Frames, new: Frames, today: date) -> pd.DataFrame` с колонками
  `kind, institute, study_form, group_name, date, day_idx, time_from, week_type, subgroup, before, after, teachers, rooms`.
- `history.refresh(conn, min_ratio, major_ratio, tz)` — обрабатывает снапшоты без статуса по времени сбора.
- Тесты diff: added, removed, changed (аудитория) с «было → стало», moved, week_published,
  week_removed (только будущая), прошедшие даты не сравниваются, major_update по форме.
- Тесты history: неполный снапшот не публикуется и не даёт изменений; следующий сравнивается с последним опубликованным.

### 3. Актуальное расписание
- `current.frames(conn) -> Frames | None`; `current.published(conn) -> pd.DataFrame`.
- Тесты: недатированные — из последнего; неделя, пропавшая из последнего, остаётся;
  дата до переделки — из версии, собранной не позже даты; будущая — из свежей.

### 4. Collector
- `collector.run_once(...) -> dict` (статус); одинаковый сбор удаляется; `run_forever` — цикл по `COLLECT_TIMES` и файлу запроса.
- Тесты: дубль удаляется, статус пишется; ошибка парсера → статус с сообщением, без исключения.

### 5. Сообщения
- `feedback.store`: `connect(path)`, `add_report(conn, fields, ip) -> int | None` (None — лимит),
  `list_reports(conn, status=None)`, `set_status(conn, id, status, note)`, `counts(conn)`.
- Тесты: миграция идемпотентна; лимит; журнал; длина текста обрезается.

### 6. Public
- `public/data.py` — кэш актуального расписания по mtime, индексы и поиск.
- `public/week.py` — занятия недели для группы/преподавателя/аудитории.
- `public/ics.py` — календарь.
- `public/app.py` — маршруты; шаблоны в `public/templates`, CSS/JS в `public/static`.
- Тесты (TestClient на mini-снапшоте): главная, поиск, группа, преподаватель, аудитория с `/`
  в имени, изменения, .ics валиден, форма → 303 и запись, ловушка → без записи, пустая база.

### 7. Staff
- Меню по спеке, `overview.py` удалить, фильтры: без выбора снапшота, «Дополнительно».
- Новые страницы: `summary.py`, `changes.py`, `reports.py`, `history.py`.
- Тесты: smoke всех страниц на данных и без; смена статуса сообщения.

### 8. Развёртывание и документация
- Dockerfile (зависимости public), compose (parser, collector, public, staff, proxy), `deploy/nginx.conf`,
  `.env.example`, README (прод-раздел, мощности).
- Проверка: `docker compose up --build`, обход страниц curl'ом.
